# 非内置插件生态：产品设计

状态：评审草案（2026-10-15）。本文定义目标与发布规则，不表示功能已经上线。

## 1. 产品定位

OpenMuse 插件商店同时面向用户、开发者和审核运营。它应回答三个问题：用户能否在当前设备和 Host 版本使用；开发者怎样按稳定合同开发并提交；平台怎样证明发布包可信且可撤回。首期免费、精选与人工审核；支付、广告和开放第三方源留作独立决策。

一个 `pluginId` 是跨端逻辑身份。每个 release 固定版本、发布者、来源仓库提交、权限、许可和一组**分别验证**的 artifact。平台标识只来自实际通过 TCK 的 artifact。Desktop、Mobile、Web 可以只支持其中一端，不能用“同名”冒充跨端可用。内置插件仍随 App 发布，可出现在同一目录，但其安装按钮和版本语义与外部插件不同。

## 2. 用户旅程

| 角色 | 旅程 | 必须看见的结果 |
| --- | --- | --- |
| 使用者 | 发现 → 详情 → 查看设备兼容与权限 → 安装计划 → 安装/启用 → 更新/禁用/卸载 | 安装实际在哪台设备执行、需哪些权限/依赖、是否需重启、失败后的恢复动作。 |
| 开发者 | 注册发布者 → 选模板 → 本地预览/TCK → 打包 → 上传 → 查看扫描/审核 → 灰度 → 观察崩溃与撤回 | 每一步有明确状态、错误码、可复现的 TCK 报告、版本与 target 的实际可用范围。 |
| 审核员 | 查看来源/许可/权限 diff、扫描报告、实机演示 → 批准/拒绝/下架 | 审核决策与签名发布分权、留痕；高风险更新可以暂停。 |

详情页至少展示：名称、维护者与验证标识、适用端/发行渠道、兼容版本、功能截图、请求权限及用途、外部网络域、数据处理说明、许可与源码、版本更新、依赖、投诉/举报入口。版本、安装数和评价仅用真实数据。iOS 还需要可供外部审查的软件索引和 universal link；Apple 当前 4.7 条款要求软件索引、用户举报/屏蔽、年龄限制，并对 Native API 暴露和数据权限另有限制。[Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)。

## 3. 插件类型与交付政策

| 类型 | 产品承诺 | 发布要求 |
| --- | --- | --- |
| Desktop 外部进程 / WebView 插件 | 由 Desktop Host 安装，独立进程或受控 WebView 运行；通过 Broker 获取能力 | Manifest v2、精确 target、签名包、权限、安装事务、健康检查与回滚。Flutter AOT 插件仍只能随 App 构建。 |
| Mobile A2UI + QuickJS 插件 | 受控 A2UI 预览或页面，由内置 Flutter Catalog 绘制，业务动作由受限 JS 与 Broker 处理 | 精确 A2UI profile/JS ABI、消息和资源预算、每个 action 的权限与回执、Android/iOS 实机 TCK。 |
| Mobile A2UI 预览 + WebView 详情 | 预览仍由 Flutter 绘制，签名 HTML/JS 详情由隔离 WebView 显示 | 资源离线打包、CSP、导航白名单、按插件作用域的消息桥；不可借 WebView 绕过 Broker。 |
| OpenMuse Web 插件 | 仅开放经过审查的声明式 Surface 或隔离的 Web 扩展点 | 明确浏览器权限、CSP、来源隔离、同源会话/CSRF 和目标浏览器 TCK；不让第三方脚本进入 Flutter 主应用的特权上下文。 |
| DSH 插件 | DSH 自己的 npm/profile 生态；OpenMuse 只做受控目录映射与安装计划 | 与 OpenMuse artifact 分列；必须通过 DSH 正式管理接口，不能由商店服务直接写用户 profile。 |

**Mobile 的产品决策点**：代码里同时存在 QuickJS/A2UI 市场演示和新的 A2UI 预览 + WebView 详情路径。首期外部发布先允许经过 TCK 的声明式预览与受控 WebView 详情；QuickJS 作为独立审核等级，待能力 Broker、资源预算和 iOS 政策评审通过后开放给普通开发者。不能把已有样例视作公众上传能力。

## 4. 用户权限与状态

“已上架”“可安装”“已安装”“已启用”“正在运行”是不同状态。服务端拥有上架和撤回状态；设备 Host 拥有安装回执、权限 grant、进程健康与数据；账号仅同步收藏和偏好，不能替设备宣称插件已安装。Mobile 管理配对 Desktop 时，页面展示明确设备名，安装由 Desktop Host 生成并执行计划。

高风险权限（文件写入、网络出口、Secret、Agent 命令、Desktop 执行、配对设备操作）逐项说明用途；权限增加必须重新取得用户同意。更新若改变运行时、数据迁移或权限，同样展示差异。禁用后不能再进入新路由。离线时“已安装”可用；目录和安全状态使用最后一次已验证快照并标明检查时间。遇到已知撤回/紧急封禁时停止新安装与新激活，保留数据与修复入口。

## 5. 运营与治理

发布者可为个人或组织，`pluginId` 命名空间须验证控制权；不可改写已有版本或以同名抢占所有权。维护者转让、版本下架、漏洞响应、隐私申诉、知识产权投诉和长期无人维护各有操作记录。官方精选与“已验证发布者”是不同标签。首期人工审核所有新发布者、首次上架和权限扩大的更新；低风险补丁可在自动化门禁后加速审核。上架后的行为举报必须有处理时限和撤回机制。

## 6. 首期成功标准

1. 一名外部开发者可按文档从模板完成一个 Desktop 与一个 Mobile 示例，运行 TCK，上传并拿到可解释的审核结果。
2. 用户在真实设备只看到可用版本；安装/更新失败不损坏旧版本和数据，重启后能恢复事务。
3. 恶意或误发布版本可停止新安装，已安装设备可收到修复/禁用建议，客户端不信任未签名的 API 响应。
4. 三端每个可用徽标都有对应 artifact、兼容矩阵和真实端到端验收证据。
