# Muse CI 产品功能

> 2026-11-19 更新：当前版本/需求双层流程、Step 规则、人工标过及 SmartDoc 文档协作以 [生命周期新规范](07-LIFECYCLE-AND-SMARTDOC.zh-CN.md) 为准。以下旧画布和原型记录作为历史基线保留。

版本：0.2 开发实现，2026 年 11 月 18 日。目标平台：OpenMuse macOS 官网版、Android 与 iOS；其他发行渠道按 Host 兼容验收决定。

## 产品定义

Muse-CI 是可后装的 AI 原生交付插件。用户描述目标，AI 将它整理成可审查的计划，在已授权范围内执行并交付证据；遇到预算、权限、产品选择或发布决定时提出具体问题。Desktop 与 Mobile 共用项目、交付和证据，区别只在布局与输入方式。

产品的主要对象是“交付”，不是聊天记录。一项交付将需求、计划、改动、检查、包和发布结果串在一起。对话用于规划及解释；实际执行状态以服务端记录为准。

## 用户与任务

| 用户 | 主要工作 | 最需要的信息 |
| --- | --- | --- |
| 产品负责人 | 定义目标、锁定范围、处理名称及体验决定 | 本次范围、待决定事项、改动影响 |
| 开发者 | 查看计划、改代码、处理检查失败 | 输入版本、改动、失败证据及修复建议 |
| 测试人员 | 检查真实运行结果与设备行为 | 检查覆盖、环境、原始报告及缺项 |
| 发布负责人 | 核对候选包、材料和渠道状态 | 来源、制品、审批、真实上传/审核记录 |
| 手机用户 | 发起任务、跟踪进度、处理阻塞 | 当前进展、下一步、需要本人决定什么 |

## 成功标准与不做项

主流程：新建交付 → 审阅计划 → 保存并运行 → 看进度与证据 → 处理决策 → 准备发布。任一页面能回答当前状态、下一步和操作影响。

首版后端能力按既有架构分阶段交付。UI 不包含 Host 私有 API，不自行读取仓库或密钥，不以本地按钮模拟真实上架成功。版权检查提供来源与证据，不作自动法律结论。

产品评估关注交付完成率、从提出目标到首份有效证据的时长、阻塞等待时间、重复执行率、取消收敛率及真实发布失败原因。原型不填造业务统计。
