# DevKit 插件产品功能

## 产品目标与用户

开发者在 OpenMuse 内完成“选择能力 → 初始化项目 → 编写代码 → 本地调试 → 真机验证 → 提交审核”，全过程可通过公开文档、SDK 和二进制发行包完成。核心验收样板是一个同时使用 PPTX、PDF 和 Agent 的资料讲解插件，不能把单格式演示作为多能力建设完成的证据。

| 用户 | 主要需要 |
| --- | --- |
| 普通开发者 | 可组合能力、类型提示、代码编辑、调试、发布 |
| 手机创作者 | 描述需求、Agent 生成、手机预览、设备验证、提交 |
| 能力提供者 | 发布 API、Mock、契约测试，查看下游兼容性 |
| 团队开发者 | 导入已有项目、共享锁文件、CI、版本迁移 |

## 插件形态和入口

拟定插件身份为 `io.openmuse/developer-kit`，展示名“插件开发工具”。从市场安装后，可在工作台打开，也可通过资源操作“基于此资源创建插件”进入。DevKit 提供普通 MCP Apps 工作页面；首版采用完整页面，Host 在支持时可将其放入工作台分区。侧栏停靠不是 MCP Apps 自带保证，不能要求开发者操作 Host 布局内部对象。

DevKit 停用后入口移除，运行任务按规则停止，项目文件保留；卸载只移除插件、缓存与会话，不删除开发者工程。重新安装可重新授权并导入项目。DevKit 更新采用发行包更新机制，不通过热更新改写自身已审核代码。

## 信息架构

```text
插件开发工具
├── 项目首页：创建、导入、最近项目、环境检查
├── 能力中心：合同、Provider、平台、版本、数据处理说明
├── 项目工作区
│   ├── 文件与代码：编辑、诊断、搜索、差异、版本记录
│   ├── 能力与依赖：功能、依赖图、锁定版本、缺失项
│   ├── Agent：需求、计划、修改差异、执行记录
│   ├── 运行与调试：Mock、发行包、日志、调用链、重载
│   ├── 设备与测试：Dev Host、Android、兼容矩阵、证据
│   └── 发布：检查、构建产物、上传、提交、审核状态
└── 设置：市场提供商、Runner、开发设备、缓存、权限
```

## 功能需求

| --- | --- | --- |
| PRD-01 | 插件生命周期 | 安装、打开、停用、升级、卸载均可验证；工程持久保留 |
| PRD-02 | 多能力选择 | 一个项目可选择任意多个已发布合同；PPTX/PDF 只是实例 |
| PRD-03 | 依赖计划 | 自动解析平台、版本、Provider、权限与传递依赖，展示冲突和安装计划 |

| PRD-05 | 应用内开发 | 编辑、类型提示、诊断、搜索、保存、差异、测试入口完整可用 |
| PRD-06 | Agent 开发 | 复用用户选择的 Agent 插件，按项目授权修改并展示差异 |
| PRD-07 | 调试 | Mock 与真实 Provider 清晰区分；重载当前插件，保留依赖会话 |
| PRD-08 | 真机验证 | 桌面和 Android 实测分别记账，按产物摘要生成证据 |
| PRD-09 | 发布管理 | 上传、待审、批准、拒绝、上架、下架可见且可追溯 |

| PRD-11 | 手机创作 | App 内编辑与预览；需要构建时选择已授权的远端 Runner |
| PRD-12 | 可恢复与可迁移 | 重启恢复工程、任务状态和锁文件；导出后可由 CLI/CI 继续开发 |

## 多能力选择与自动解析

开发者输入“做一个可以讲解 PPT 和 PDF，并能比较两份资料的插件”。DevKit 将需求整理为可编辑的功能列表：

| 功能 | 能力依赖 | 资源 |
| --- | --- | --- |
| PPT 讲解 | slides.read、slides.preview、Agent.generate | PPT 资源 |
| PDF 讲解 | pdf.read、pdf.preview、Agent.generate | PDF 资源 |
| 双资料比较 | slides.read + pdf.read + Agent.generate | 两份分别授权的资源 |
| 语音播放 | Voice.speak | 生成的讲稿，可设为可选功能 |

能力使用公开合同 ID 标识。UI 展示人类可读名称、支持端、调用示例、数据是否离开设备、Provider、维护者和测试状态。自然语言建议由开发者确认后成为项目需求，不能静默新增网络或写权限。

“自动选择”包含生成候选及确定性解析；确定唯一且满足既有授权时可直接继续。多个实现可用时优先项目已有绑定、用户偏好及兼容结果，允许切换 Provider 并查看差异。缺失、已下架且不能新装、版本冲突、平台不支持时应显示具体阻塞项。

支持“每个功能的全部依赖”和“同一能力的可替代实现”两种关系。两个必需合同不能因同属文档类别而合并成任意选一。支持 PPT/PDF 分别打开，与同时打开两份资料进行比较，是两个不同的验收场景。

提供者解析先生成计划，安装由 Host/市场安装能力执行；DevKit 不写其他插件的安装目录或用户 profile。能力可用性按端和功能展示，不能仅给一个全局“已兼容”标记。

## 项目创建和已有工程

创建向导依次选择：项目名称与命名空间、目录、模板、目标平台、Host 版本、功能与能力、Runner。默认 Host `latest` 当场解析为精确构建并锁定，后续打开项目不自动漂移。

初始化生成源码、语言包配置、公开开发配置、锁文件、能力客户端、Mock、测试夹具和 CI 示例。目录非空时展示预览，禁止覆盖现有文件；失败回滚本次创建的临时文件。导入项目时先只读检查，不自动执行安装脚本。

支持 SDK 模板、资源协作插件模板、轻量表单模板、能力提供者模板。模板与运行依赖均锁定版本和来源。

## 应用内代码开发

Desktop 页面布局为文件树、编辑器、预览及诊断区；窄屏以文件、代码、预览、Agent 四个页签切换。提供文件读写、撤销、保存状态、文本搜索、类型诊断、格式化、错误跳转和多文件差异。代码编辑器不是 iframe 内的任意系统终端。

首版集成轻量代码编辑组件；完整 IDE 插件后续可通过公开资源编辑能力接入。开发者可选择外部 IDE 作为补充，应用内主流程保持可完成。项目操作和构建操作均经过受限 Workspace/Runner 能力，不向页面开放无边界文件系统或 shell。

Agent 看到项目合同、SDK 文档和被授权文件。修改采用补丁预览及版本检查；不提供审核员密钥，也不继承其他 Agent 的完整 Workspace 权限。界面操作和 Agent 工具调用应形成同一条可回放的项目操作记录。

## 调试与设备

支持 Mock、真实发行包、真实设备三种模式，常驻标识当前模式。启动前展示目标 Host、依赖版本、资源授权、可用功能和数据去向。开发包单独标识并只装入开发通道；生产市场不因启动调试而出现条目。

调试界面显示构建、安装、连接、能力发现、资源传输、Provider 执行、视图启动步骤及耗时。有总量时显示真实进度，没有总量时显示不确定进度。日志隐藏 token、原文、绝对用户路径及凭据。

重载消费者插件时保留 PPT/PDF Provider 的原有文档会话；更换 Provider、合同主版本或资源授权时重新绑定。文档关闭或授权撤销后暂停调用和讲解，提示恢复操作。

## 发布流程和权限

发布页展示包摘要、精确目标、必需/可选功能、依赖计划、测试证据、隐私与许可。检查通过后上传不可变产物并提交审核。开发者只能查自己的提交；审核员继续使用独立管理后台。

状态为 `draft → validated → built → uploaded → pending → approved/rejected`，已批准版本可为 `listed/delisted`；这些是 DevKit 展示状态，实际市场响应由适配器映射。上传成功不能显示“已上架”；拒绝后修改要创建新候选版本。上架后正常使用不依赖 DevKit 已安装。

## 产品成功指标

以下为验收目标，需在实现后采样，不是当前测量结果：

- 新开发者用公开资料和发行包，在干净环境内完成双能力样板，不检出 Host/GenOffice/PDF Provider 源码。
- 创建工程、编辑、调试、提交审核都可由 DevKit 页面完成，CLI 为可选。
- 同一项目的 PPT、PDF、双资料比较分别通过；缺失可选 Voice 时仍可文字讲解。
- 运行失败可定位到当前步骤和责任 Provider；关闭文档不继续读取或播放。
- 断网可继续编辑、查看已缓存合同并运行可用本地测试；上传、首次下载和云端构建明确标记离线不可用。
