# DevKit 验收矩阵

## 验收规则

本矩阵保留完整产品发布门禁，不等于当前测试结果。部分底层实现已测试，详见[Desktop 证据与剩余验收](08-DESKTOP-WORKSPACE-CLI.zh-CN.md)。原生 UI 的首要旅程为：选择/创建 Workspace → 应用内终端搜索/安装 Provider → CLI 原地初始化 → 现有编辑器/Agent 开发 → 应用内候选调试 → 提交待审。报告必须关联消费者、Provider、合同、SDK、Host 和产物摘要；Mock、协议 harness、Dev Host 和正常客户端四种证据分别记录。

固定样例包括一份多页 PPTX、一份有文本层的多页 PDF、一份无文字层或加密 PDF、一份用于错误测试的损坏文件，以及不同版本的 API/Provider 夹具。样本许可与摘要入报告，用户原文件不被编辑测试覆盖。

## 双格式样板操作脚本

1. 在正常 OpenMuse 安装 DevKit，选择已认证的目标 Host 构建。
2. 在页面创建独立工程，选择 PPT、PDF、比较功能及 Agent；Voice 为可选。
3. 自动解析两个文档合同及其 Provider，显示每端可用性，生成工程和锁文件。
4. 在内置编辑器改变功能代码，通过 Mock，确认报告仍标为 Mock。
5. 启动隔离 Dev Host，仅安装 GenOffice/PDF/Agent 发行包及当前消费者候选包。
6. 分别打开 PPT 与 PDF，验证文本、备注/页面预览、导航和讲解。
7. 同时选择 PPT/PDF，分别授权，验证比较结果确实引用两份资料。
8. 手工修改 PPT 未保存内容后重读；切换焦点和重载消费者，不重载 Provider，不丢内容。
9. 撤销一份资源授权、关闭文档、禁用一个 Provider，分别验证停止、提示与重新绑定。
10. 拒绝资料出站权限，确认远端 Agent 无法通过其他 Provider 绕过；纯本地功能继续按实际能力运行。
11. 安装完整 Android 开发应用及同一候选版本，重做单格式和双资料流程。
12. 收集报告、打包、上传、提交，审核通过后在正常客户端新装运行；下架后新安装不可见。

## 故障注入与数据保护

| 注入 | 通过条件 |
| --- | --- |
| 同一 Provider 的版本要求无交集 | 显示冲突，未安装混合版本冒充兼容 |
| 传递依赖循环 | 解析结束并返回循环路径，不无限递归 |
| 相同工具名出现在不同 Provider | 别名明确，路由正确且无串文档 |
| 文档 URI 重用、旧请求晚到 | 旧会话失败，新资源不接受旧调用 |
| 只有一个资源被授权 | 比较功能不读取另一份资源，提示第二次授权 |
| PDF 为扫描件、加密或损坏 | 明确返回需要 OCR/密码或不支持，不生成伪造正文 |
| 网络或云 Runner 超时 | 显示具体阶段、取消/重试，任务状态可查询，凭据未泄露 |
| SDK Schema 与 Provider 输出不符 | 明确拒绝并给版本诊断，不在业务代码猜字段兼容 |
| DevKit 卸载或客户端退出 | 本机任务终止/清理，远端任务按策略取消/可查询；项目不被删除 |
| Dev Host 调试凭据用于生产或其他设备 | 拒绝且有审计，生产安全策略不降低 |

## 报告与发布证据

报告包含：场景 ID、消费者与依赖版本/摘要、合同摘要、Host 版本/构建/摘要、系统/WebView、运行模式、起止时间、步骤耗时、结果、错误、脱敏日志和截图/视频的摘要。设备身份仅记录必要信息，不公开序列号或账号凭据。

每个功能的结果为 pass/fail/unsupported/not-run，unsupported 必须体现在产品支持范围；不能把未运行记为 pass。性能目标在 M0 建立基线后冻结，至少分别测初始化、增量构建、消费者重载、Provider 调用、传输、渲染、内存峰值，不能把下载完成当成页面渲染完成。

最终发布门禁包括正常客户端验收、审核状态与目录一致、包摘要不变、开发签名/调试端口不进入正式包、用户数据与密钥未进入报告。已发布消费者卸载 DevKit 后仍可运行，证明工具链不是运行时隐藏依赖。
