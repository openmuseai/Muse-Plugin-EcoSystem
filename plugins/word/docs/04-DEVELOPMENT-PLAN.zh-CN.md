# 详细开发计划

联合版本、构建、测试、发布和回滚流程见[持续迭代工作流](06-CONTINUOUS-DELIVERY.zh-CN.md)。每一阶段进入候选版前运行同一联合命令，并将报告与版本清单归档。

GenOffice Docs 壳层的源码清单、1:1 验收定义、领域模型与 G0–G5 任务见[壳层复刻计划](07-GENOFFICE-CHROME-PLAN.zh-CN.md)。该计划细化本文件 M2 的 UI 工作，不能替代 M1 的内核编辑与保存门禁。

计划以**可验收的阶段门禁**排列，时间是团队排期估计，不代表已经完成。M0 与 M1 的接口工作可并行；M3 以后依赖可保存的内核与已安装资源加载器。每阶段保留 Desktop、Mobile、Web 的实际状态，不把单端通过记为三端完成。

| 阶段 | 预计 | 仓库与任务 | 完成门禁 |
| --- | --- | --- | --- |
| M0 合同冻结 | 1 周 | 本仓冻结 `openmuse-word-product/1`、命令 ID、能力名和签名目录；`Muse-Client`/`ioffice` 共同确定会话、修订、导出与模板 API | 三仓合同评审通过；非法资源、未知命令、版本不兼容均可机器拒绝 |
| M1 内核产品基线 | 依现有改写进度 | `ioffice` 完成 `WordSession` 事务、撤销/重做、样式操作、DOCX 导出/重开、模板实例化；保持模型与分页唯一 | 同一 DOCX 编辑→保存→关闭→重开无数据丢失；Java/Rust 关键样本差异达到商定的产品门槛 |
| M2 编辑表面适配 | 1–2 周 | `ioffice` 将 Ribbon、快捷键和功能门禁改为外部配置输入；保留画布、光标、选区、输入法、滚动在 Flutter 包；补充命令状态回传 | 不安装 Word 包时不出现 Word 入口；安装测试包后配置决定可见按钮；逐字输入无需插件 IPC |

| M5 Mobile 离线 | 2–3 周 | `ioffice` 构建 Android/iOS 原生内核随 Host；Host 读取已签名静态资源、存储文档、处理输入法及应用恢复；扩展运行时未通过则保持禁用 | Android 与 iOS 真机断网、杀进程后打开/编辑/保存/重开；安装、更新、回滚、卸载均不丢文档 |
| M6 Web 离线 | 2–3 周 | `ioffice` 完成 Rust WASM 运输、字体注入与 Flutter Web 适配；Host 缓存签名包和内核、持久化文档、按需恢复 | Chrome/Firefox/Safari 目标矩阵明确；断网重载后可编辑保存；WASM 不可用时明确不支持或实现经过验证的备用内核 |
| M7 发布认证 | 1–2 周 | 本仓签名发行、市场审核与撤回；三仓性能、保真、可访问性和升级矩阵；生产公钥轮换演练 | [验收矩阵](05-ACCEPTANCE.zh-CN.md)通过，有可追溯版本和回滚方案后上架 |

## 当前工程已完成与未完成

本工程已提供静态产品资源、引用校验、MCP 资源发现 Server、显式字数统计逻辑、Ed25519 打包/验签和篡改测试。首版还完成 macOS Host 签名资源加载、DOCX 原生路由和只读渲染 E2E：样本文档在完整 OpenMuse 进程中打开，生成 8 页、187 条绘制命令。这只完成 **Desktop 预览子集**，不表示 M1–M7 的完整编辑门禁通过，也没有生产签名或市场上架。

主要外部依赖：

1. `ioffice` 当前 FRB 接口能打开、排版及部分编辑，但 DOCX 保存实现尚有 `todo!`；复杂文档的打印级保真验收仍失败。M1 是能否宣称“离线编辑”的关键路径。
2. 首版 Host 从签名资源读取 Ribbon/命令/功能开关；新壳已显示八个常规页签、首页控件骨架和状态栏，实际可用命令仍只有打开/缩放。完整菜单、快捷键、选区命令状态流与安装版本切换机制仍属 M2/G2–G4。
3. Host 已在 Desktop 识别 Word Product Profile 并内嵌 `word_editor`；生产信任根、安装回滚和 Mobile 产品资源链仍属 M3/M5。
4. Web 的 `word-core` WASM 运输是独立工程。Flutter Web 自身的 WASM/JavaScript 后备不自动成为 Rust 内核后备；M6 要实测浏览器能力、字体与离线缓存。

## 任务拆分与交付顺序

### M0：共同合同与插件资源

- [x] 建立本目录、命令/Ribbon/快捷键/模板/字体目录/功能门禁资源。
- [x] 建立资源引用校验、签名目录与签名包测试。
- [ ] 与 Host 和内核负责人冻结 `word.command/1` 请求/结果、能力列表、版本与错误码。
- [ ] 发布公开 Profile 规范与消费端一致性测试样例。

### M1：`ioffice` 内核

- [ ] 给每次编辑产生单调修订与可撤销事务；内核掌握唯一选择和格式状态。
- [ ] 实现当前功能区声明的粗体、斜体、下划线、撤销/重做；未实现时发行包继续关闭 `word.edit`。
- [ ] 实现可验证 DOCX 导出、格式保留和失败回滚；通过后才开启 `word.save`。
- [ ] 模板 JSON 由内核生成新文档；字体字节注入测量和绘制两侧。
- [ ] 对大文档建立增量排版或可视区优化；记录内存、首次打开和编辑延迟基线。

### M2/M3：Flutter 编辑表面与 Host

- [ ] `word_editor` 公开 `WordProductConfig` 输入与命令回调，Ribbon 不再内置产品命令列表。
- [x] Desktop Host 校验签名和静态资源后注册只读 Word 预览，并在打开会话期间持有当前配置。
- [ ] 完成正式安装快照、版本锁和升级切换机制；升级不在编辑会话中途替换布局。
- [ ] 统一文档打开、保存、权限撤销、外部文件修改冲突、崩溃草稿恢复。
- [ ] 原生字体许可、文件摘要和平台字体匹配规则进入发行门禁。

### M4–M7：平台与发布

- [ ] Desktop 两种窗口形态的资源租约、焦点、剪贴板、输入法和缩放一致性。
- [ ] Android/iOS 真机离线安装与编辑；检查平台应用商店对可下载脚本扩展的要求。
- [ ] Web WASM、资源缓存、离线重开和数据持久化；浏览器不支持时给出明确能力反馈。
- [ ] 签名密钥轮换、撤回、升级/降级兼容、市场审核和证据归档。

## 风险控制

| 风险 | 处理方式 |
| --- | --- |
| DOCX 保存尚不可用 | 保持编辑/保存功能门禁关闭；不得发布为完整编辑器 |
| Wordcraft UI 代码与自身模型强耦合 | 仅提炼交互设计与命令语义，不复制 egui Session/Document/DocLayout 依赖 |
| Flutter AOT 动态 UI 限制 | 内嵌 UI 随 Host 构建；插件独立更新配置与资源；独立窗口程序可单独发行 |
| 多端脚本执行差异 | 扩展声明同一输入/输出合同，未通过目标平台适配就关闭，不影响基础编辑 |
| 字体与打印保真 | 固定合法字体字节和摘要，用同一文件做内核度量与 Flutter 绘制；建立金文件与视觉基线 |
| 离线缓存损坏/升级失败 | 包与文档分目录，先验证再原子切换，保留上版和用户文档 |
