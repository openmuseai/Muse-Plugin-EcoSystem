## B：完整知识库工具的后续迁移

这些属于完整产品适配的剩余工作，不由 A 阶段的通过推导为已完成。

| 顺序 | 任务 | 实施约束与验收 |
| --- | --- | --- |
| B1 | 原有知识库作为插件资源源/集合提供 | 采用可选通用 Provider contributor，由插件维护稳定 notebook/document/block 身份及版本；Host 只消费 Provider。提供明确的整本导入/迁移预览，不逐篇无提示复制，不更改旧 userdata |
| B2 | 大纲、搜索、反链、标签、图谱 | 作为当前资源的插件上下文操作/面板；Host 提供容器，插件提供解释与查询，不重建左右全局 Dock；跨 PC/手机的权限及离线状态继续由共享资源核心控制 |
| B3 | 跨资源块引用与附件路由 | 同包跳转已实现；包外链接还需稳定块子资源身份和来源 Provider。附件交给本机实际可用的 PDF/图片等 handler；不把 loopback URL、cookie 或临时内核 ID 放进长期引用 |
| B4 | 闪卡、模板、历史、OCR/批注与文档导出操作 | 按真实能力逐项贡献到资源菜单/上下文；历史包保持固定版本只读。OCR/平台格式导出需各端实际运行，不以核心引擎存在宣称 UI 已验收 |
| B5 | 完整知识库数据迁移验收 | 原始库副本、跨文档/跨本引用、资产注释、数据库关系/独立行、加密导出、闪卡、模板，原子回执/失败恢复、跨账号作用域和多资源并发矩阵 |

## 共享框架原则

后续 Word、Excel、PPTX 的新增能力应复用 `ResourceHandlerSpec`、`ResourceCreatorSpec`、`ResourceEditorSession` 与通用 presentation callback。编译插件可直接实现公开 SDK contributor；下载式 MCPB 的创建/编辑扩展需版本化能力协商，不能往冻结 manifest v2 塞字段。外部物理 Workspace 目前按资源中心 P0 契约只读，不通过插件绕过权限实现假写入。

人工复核期间不自动提交、推送或上传商店。三端硬件/模拟器、构建与可视截图分别记录；缺少设备许可或 Mac 锁屏时明确列为待验收。
