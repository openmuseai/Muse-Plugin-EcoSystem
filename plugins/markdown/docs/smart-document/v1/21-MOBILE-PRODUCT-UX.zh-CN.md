# 智能文档 Mobile 产品与完整交互规格 v1.3 实施基线

2026-11-05。变更记录：**CR-SD-MOB-20261105**。输入：[实机参考](20-WPS-MOBILE-REFERENCE.zh-CN.md)、原 [PRD](04-PRODUCT-PRD.zh-CN.md) / [交互稿](05-UX-SPEC.zh-CN.md)。此文件补齐手机布局及完整功能区，不覆盖既有冻结快照；依据用户“已初步对齐，落实交互和视觉稿后继续实施”的指令，作为 SD-MOB-1.3-20261105 开发输入归档；冻结的是目标与交互，运行产品的覆盖率独立记录。

## 1. 产品目标与层级

目标是在手机上连续写作、阅读材料、处理团队讨论和 Agent 任务，并保持 Desktop/Web 的同一内容/协作语义。视觉以当前手机 WPS 的阅读、编辑、键盘、浮层结构对齐；资源和协作能力依旧由 Muse 插件/领域内核提供。

| 逻辑区域 | 阅读 | 编辑但键盘隐藏 | 键盘输入 | 图片/表格等上下文 |
| --- | --- | --- | --- | --- |
| 顶部 | 头像、分享、评论、更多、资源切换、关闭 | 完成、undo/redo、更多、资源切换、关闭 | 同左，光标不能被顶部遮挡 | 相同导航；undo 属于当前活动 surface |
| 正文 | 连续内容、封面/页面、标题、元信息 | 同一内容进入可编辑状态 | 可视高度随 IME/insets 改变，滚动当前光标 | 保留来源与选择边界，可进入子编辑面 |
| 底部 | 编辑/聊文档/目录/视图浮动胶囊 | 完整八入口编辑工具栏 | 同一工具栏移到键盘上方 | 工具按上下文启用/禁用；块工具出现在选中材料附近 |
| 弹层 | 目录、视图、评论、分享、文件操作 | 同一能力入口 | 列表/对齐保留 IME；Aa/插入等有独立面板 | 表格和外部资源有独立命令与选择模型 |
| AI | 从“聊文档”进入受限阅读/任务范围 | 从 AI 进入写作辅助 | AI composer 替代普通编辑工具区，键盘保留 | 不自动获取无权读取的嵌入原文 |

标题是文档数据，重命名不是另存；个人视图是本地偏好；共享页面样式是有权限的领域命令。不能把所有层的状态都写到一份“页面设置 JSON”。

## 3. 键盘上方完整功能区

### 3.1 布局与几何

默认目标手机逻辑宽 390/393，正文左右留白约 24；同时检查 320、360、430。状态栏、安全区、键盘高度来自系统，不能硬编码为某个截图的像素。工具栏约 50–52 高，图标约 24，点击区域至少 44；正文承担剩余高度并能将光标滚入可见区域。

八项顺序固定为 **AI / ＋ / Aa / 列表 / 对齐 / 图片 / @ 用户 / 键盘开关**。宽屏完整呈现；极窄屏保留触控尺寸，前七项横向可达，键盘开关固定末端，不压成 30 像素小按钮，也不自动换成两行挤占 IME 上方空间。屏幕阅读器与外接键盘可逐项到达隐藏在横向区域中的工具。

| 状态 | 普通工具栏 | 系统键盘 | 面板/浮层 |
| --- | --- | --- | --- |
| 编辑/键盘隐藏 | 固定安全区上方 | 隐藏 | 无 |
| 正文输入 | 紧邻键盘顶部 | 显示 | 无 |
| 列表 | 保持，列表项高亮 | **保持** | 工具上方三图标紧凑浮层，无整屏蒙层 |
| 对齐/缩进 | 保持，对齐项高亮 | **保持** | 五动作紧凑浮层；缩进组有分隔线 |
| Aa | 不与另一条工具栏重复 | 收起或平台动画完成后切换 | 可滚动“调整样式”面板，关闭恢复原插入点 |
| 插入/多步资源选择 | 保留原选择快照 | 与选择器互斥 | 插入面板→来源选择→预览/确认 |
| 图片块选中 | 文字样式/列表/对齐禁用并说明上下文 | 通常收起 | 图片源控件＋块上下文 |
| AI 输入 | **由 AI composer 替换** | **保持** | 功能建议浮层，AI 任务输入/思考入口；退出恢复普通工具栏 |

系统键盘里的语音、表情、候选词、语言切换归输入法，不复制进应用自己的功能清单，也不在 Flutter 中自绘一套假系统键盘。视觉稿中的键盘只用于验证布局。

### 3.2 选区与返回

打开 Aa、列表、对齐或资源选择时保存 `activeSurface + anchor + focus + affinity + domainSelection + revisionContext`。返回时恢复映射后的合法选区；目标被删除则提示重新定位，不能把操作落到文档开头或其他资源。

文字范围、表格区域、图片块、嵌入页/区域各自有 selection adapter。工具栏只发语义 command，不凭屏幕坐标、剪贴板文本或 Flutter node path 作为长期身份。远端编辑不抢走本地焦点；结构变化后重新映射。

返回优先关闭当前最上层浮层/选择器，再处理键盘/选区，再退出编辑，最后关闭资源。Android Back、iOS 返回/手势、顶部完成和关闭分别映射到这个状态栈；一次 Back 不同时关面板、丢光标和退文档。顶部“完成”完成编辑，不等于关闭资源或等待云端耐久。

本机提交失败时保留当前草稿并说明失败；不能把“完成”显示成云端成功。后台/隐藏时触发有界 flush，恢复后校验权限/引擎绑定并追赶；OS 杀进程只承诺恢复到真实持久边界，不承诺尚未提交的 IME composing 字符必然安全。

## 4. Aa 与颜色的完整状态

实机文本类型是 H1–H6/正文，而 F1 工程切片是 H1–H3。设计此次覆盖完整类型；新增 H4–H6 命令、跨端呈现和格式桥按 CR-SD-MOB 追踪，不把原 F1 报告改成“早已实现”。

B/I/U/删除线有 on/off/mixed/locked 状态；例如实机 H1 的加粗不可用属于已观察的固有样式状态，不能笼统解释为没有实现加粗。普通文本取消某种 mark 不应清除所有格式或改变块类型。

字体色板包含普通色与渐变；高亮色板包含“无”。前景和高亮分别编码。渐变不能直接塞进现有只接收十六进制字符串的字段，应扩展版本化样式 token/renderer 并保留兼容读写策略；低能力端要显式只读或提示，不静默把渐变丢成黑色。此处不冻结永久 wire 字段，T02/T05 需补 Rust/Dart/schema fixture。

## 5. 插入、资源与上下文

“＋”负责创建内容/引用，“@”负责用户提及，二者不复用同一个混合 picker。云文档、本地 Word/PDF/Excel/PPT、图片/视频、数据集或应用最终通过各自 descriptor/capability 提供可插入方式：附件、独立资源、页/区域视图或嵌入式编辑器。

上传/转换期间保留草稿和插入锚点；取消不留下空的已提交资源。图片占位块尚未选择来源时显示其来源选择动作；误插可作为当前操作者的一次 undo 撤回。素材上传完成不代表正文已经耐久，反之亦然。

手机横向宽表在自己的区域内滚动，选中单元格后出现表格工具，不把整页横向拖走。Office 进入子编辑面后归还键盘、选区与 undo owner；返回正文恢复原位置。引用移除不删除来源，引用也不自动赋予来源访问权。

## 6. AI 与协作

AI 只按用户最新约束对齐布局，不复制 WPS 全部 AI 功能。读文档/聊文档与写入建议可共用 Muse Agent 服务，但范围、读取权限和写权限分别确定；不因能读摘要就能修改正文或嵌入源。

菜单功能由 Muse 已安装 Agent/模型能力贡献，composer 提供任务输入、范围和可选思考能力。生成后先显示建议/差异，明确应用、保留草稿或取消；实际应用通过同一领域命令入口，有前置条件、幂等和来源记录。人类先改目标时拒绝旧建议，保留草稿，不把“插入回答”当作权限校验。

成员头像/presence 是短期通道；评论是持久 annotation；正文是领域状态。移动面板不把三者压成一个全局保存状态。可评论用户的原始正文 update 仍应被服务端拒绝；退到后台会话和光标按 TTL 处理。
