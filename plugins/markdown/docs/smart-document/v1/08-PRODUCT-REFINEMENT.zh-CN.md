# 产品与交互收敛：先验证用户任务，再冻结架构

> 产品/交互冻结基线：**SD-BL-1.2-20261105**。以 [冻结记录与快照](13-FROZEN-BASELINE.zh-CN.md) 为准；技术实施见 [14](14-ENGINEERING-DESIGN.zh-CN.md)/[15](15-EXECUTION-PLAN.zh-CN.md)。

2026-11-05，v1.1 补充。与 PRD/交互稿共同使用；架构变化见 [协作 package/plugin 设计](09-COLLABORATION-PACKAGES.zh-CN.md)。

## 1. 产品边界再收敛

智能文档是资源工作面之一。产品的共同基础是资源身份与受权对象，不能把全部资源改名成文档后强制塞入同一 AST。Host 提供工作区/标签/资源中心和既有 Agent 容器；智能文档 plugin 贡献编辑 surface，内容 provider 贡献专业对象，协作 provider 贡献共享连接与状态能力。

首版用户价值优先级：**写清楚 → 团队一起维护 → 引用真实来源 → Agent 修改可校验 → 小数据应用复用同一来源**。自由画布、专业媒体制作、完整低代码和全部 Office 多人编辑不会因为视觉稿中有插槽而进入首版范围。

## 2. 三条北极星任务流

| 流程 | 用户问题 | 成功结果 | 跑偏信号 |
| --- | --- | --- | --- |
| U1 团队共写发布计划 | 正文、任务与证据散落，难以保持一致 | 同页组织，任务独立打开后仍是同一数据，引用来源可定位 | 把表格复制成正文；每种材料启动第二套工作区 |
| U2 Agent 协同编辑 | 生成结果不知依据，容易覆盖人的修改 | 明确目标/来源 → 建议 → 校验 → 提交，冲突可重新读取 | 自动读取全部关联资源；把聊天回复等同已写文档 |
| U3 连网失败仍有工作成果 | 用户分不清本机保存与团队同步 | 正文按能力本机继续保存，恢复后追赶；数据集离线明确为草稿 | 停用协作就不能打开资源，或无网络仍假报共享成功 |

先用这三条路径评审，不以按钮数量、菜单完整度或一张漂亮截图判断架构成功。

## 3. 现有应用框架中的位置

Desktop 沿用 Host 资源导航、工作区标签、可选底部控制台和右侧 Agent 工作面。智能文档不再内置第二份全局 Agent、账号壳或文件树。评论/历史与资源上下文作为既有上下文区域的贡献；右栏只挂载一套活动容器，不能叠加两条同义侧栏。

Mobile 入口沿用 Home 资源中心 → 资源页，不把它重新变成工作台里的独立笔记应用。五项全局导航属于 Home 根层，进入编辑器使用返回导航和资源操作，不叠加根层 `+`。Agent/评论可折叠到资源内上下文页，返回保留滚动、选区、任务和草稿。

工作区协作与专注创作是同一资源的布局选择；它们不切换对象模型、协作协议或保存路径。Web 消费相同资源与能力合同，受浏览器实际 provider 能力约束。

## 4. 首版需求的精确解释

沿用 SD-01–SD-17，不增加未经估算的大型功能：

| 需求 | 收敛后的用户行为 |
| --- | --- |
| SD-01/06 | 资源可以单独打开，也可在智能文档里引用；移除引用不删除来源 |
| SD-02/17 | 写作、选择、输入法、快捷键/触控优先；聚焦模式只改变 chrome |
| SD-03/04 | 共享连接与本机内容状态分别可见；服务不可用不等于编辑器卸载 |
| SD-05/15 | 评论者可评论但不能改正文；权限在服务端重验，角色不由前端自报 |
| SD-07/08 | 首版至少一类真实 Office provider；视觉稿中的 PDF 是明确示例，不是产品验收结果 |
| SD-09 | 每次建议有修改目标与来源；建议、已提交、冲突分开；背景任务不依赖窗口在线 |
| SD-10/11 | 一个受限任务数据集 + 表格/看板/表单样板；不会在正文内部复制另一份工作簿 |
| SD-12 | 内容、协作与 UI 能力分开装配；package 可复用，不承诺任意原生代码热安装 |
| SD-13/14/16 | 恢复/导入/导出必须保持对象和来源语义；回退正文不自动回滚关联对象 |

## 5. 关键交互的输入、输出和失败

| 交互 | 输入 | 输出 | 失败/冲突处理 |
| --- | --- | --- | --- |
| 引用材料 | 受权 resourceRef、选择器、固定/实时绑定 | 新的引用块与来源标记 | 缺插件/来源不可读/版本失效分别说明 |
| 打开数据集来源 | 引用目标身份 | 独立标签中的同一对象/记录 | 无权不暴露摘要；不创建“临时复制表” |
| 改任务状态 | recordId/fieldId、目标版本、新值 | 更新回执和所有订阅视图变化 | 过期/离线保留草稿；不要先报共享成功 |
| Agent 生成 | 明确目标范围、指令、受权来源版本 | 未提交建议，展示目标/来源 | 缺来源可重新选择；不静默扩大范围 |
| 应用建议 | 有界 patch、目标前置条件 | 一次可追踪变更与 operationId | 目标已改保留建议，重新读取/重生成/丢弃 |
| 暂停协作连接 | provider 会话 | 网络暂停，本机支持能力保留 | 不清日志；不改本机内核/engine/schema |
| 历史预览/恢复 | 指定正文检查点 | 只读预览或新恢复版本 | 旧未同步草稿保留；依赖对象不静默回滚 |

## 6. 界面责任归属

| 界面元素 | 所属 | 消费的公开能力 |
| --- | --- | --- |
| 导航/标签/来源打开 | Host/资源中心 | ResourceRef、presentation/anchor |
| 正文工具/块菜单/引用容器 | 智能文档内容 plugin | 领域命令与元素/surface profile |
| 任务表/Office 页 | 相应内容 provider | 目标对象、投影与实际能力 |
| 在线人/共享状态 | 可选协作 UI/provider | 中立会话状态、受权参与者与回执 |
| Agent 区域 | Host 现有 Agent 容器 + 资源贡献 | 当前资源上下文、范围化工具、作业事件 |
| 插件管理 | Host 安装/能力 registry | 版本、平台、依赖与授权，不能变成格式专用分支 |

分享操作协调资源 ACL 和 provider 能力；在线状态面板本身不拥有授权表。不能因为 UI 显示“可协作”就把原始写入权限交给所有插件。

## 7. 视觉评审与实施验收分开

本轮视觉稿用于评审布局、目标对象、控制归属、状态文案和任务闭环。数据、用户、PDF 页和云端回执均为示例，不连接账号或服务。浏览器交互检查只证明原型中的行为与布局，不证明 Flutter、WASM、真实授权/协作和本地耐久已经实现。

先对 U1–U3 与窄屏/只读/连接失败等状态建立视觉基线，再反推最小公开合同；避免先铺一套广泛平台包，再让产品被实现细节牵引。Visual frame → 用户行为 → 合同 → package/plugin → 领域测试的历史追踪见 [旧评审](10-VISUAL-REVIEW.zh-CN.md)，当前功能/视觉追踪见 [12](12-FUNCTIONAL-ALIGNMENT.zh-CN.md)。

## 8. 本轮新增的设计门槛

V1：同一资源在独立页和组合页身份不变；V2：Agent 不覆盖已变目标；V3：协作不可用与只读权限区分；V4：内容内核与连接服务可独立装配；V5：Host 只保留一个全局导航/Agent 容器；V6：Mobile 不是压缩桌面截图；V7：任何视觉中出现的“能力”都能映射到实际 provider 或明确示例状态。

这些门槛用于约束设计，尚未成为运行产品的通过声明。
