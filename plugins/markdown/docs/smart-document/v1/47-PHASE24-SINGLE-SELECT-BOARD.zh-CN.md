# P24：共享原记录的单选分组看板（切片已验收）

承接 [P23 多视图共享字段](46-PHASE23-SHARED-VIEW-SCHEMA.zh-CN.md)，继续落实 [功能对齐账本](siyuan-collaboration-parity.json)。本轮先交付单选分组的看板交互与跨端协作验收，不将其记作全部思源数据库或完整协作验收。

## 产品与交互约束

数据库新增视图时可选择表格或看板。看板选择已有单选字段，复用选项名称、颜色和稳定 ID；没有单选字段时提示先新增字段，不静默创建额外 schema。视图切换仍是本地状态，不修改正文资源引用或复制记录。表格、原生看板和新增看板共享原字段与行。

卡片点击打开现有记录详情，复用数字、日期、选项、链接等类型编辑器。卡片的“移动卡片”菜单是触控、鼠标与辅助操作的明确入口；长按拖动可将卡片移到另一列。列头新增按钮创建原数据库行并明确赋值分组字段，再打开记录详情。过滤不匹配的记录仍可在详情编辑，筛选与排序沿用原实现。

嵌入看板的工具区横向滚动，保留全部工具，避免手机上多行工具挤占卡片视口；卡片列横向滚动，列内纵向滚动。原 WPS 对齐的文档顶部、阅读/编辑切换、插入入口、协作者和键盘功能区保持原设计。只读的父资源继续缩小子资源可写能力，卡片详情也必须继承该限制。

未知选项值保留原行与原单元格，显示不能分组的记录数量并提供切换表格查看的路径，不把未知值重写为空值。未知分组类型、多个竞争配置和未知配置内容不开放看板写入。分组隐藏与隐藏空分组沿用原配置；空组即使不显示，仍可从移动菜单选择有效目标。

## 源码复用与领域边界

固定思源 `ViewGroup` / `KanbanCard.ID` 作为产品语义参考。AppFlowy 原 `GroupSetting`、单选 `SelectOptionIds`、`merge_groups` 顺序和可见性，以及用字段 ID 表示的未分组列作为运行时模型。八份固定原文件及许可在 `smart_document/vendor/board_reference`，提供独立校验脚本，不修改思源原仓库，不引入新数据库或 CRDT 引擎。

Dataset Rust 内核派生分组与原行 ID 列表，读取不写 CRDT。Flutter 只渲染卡片和发送语义命令；创建视图使用原 `create_linked_view`，移动委托原类型字段 `SetCell`，新增委托原 `AddRow`。Database Root1 保存视图配置，原 Row4 保存字段值，继续使用既有 Cloud、授权、检查点、作者撤销和在线位置能力。正文只保存原资源引用，内容层与协作层没有相互嵌入。

移动命令预检分组配置与字段摘要，以及原行单元格摘要；过期菜单拒绝覆盖已观察到的远端变更。摘要仅是本地前置条件，不能保证互不知情的并发移动各自成功保留。相同单元格冲突继续遵循原 Yrs 合并语义；不同字段的并发修改应同时保留。禁止把卡片位置另存一份到视图或文档里。

## 实施与验收顺序

1. 原实现校验、领域投影及命令：纯查询、分组顺序/隐藏、并发新建看板与新增行、过期输入拒绝、独立行撤销和重开。
2. Flutter 三种宽度的真实交互：新增看板、移动、记录详情、分组内新增、只读父资源。复用现有编辑器，保留严格触控命中检查。
3. 公共资源宿主下 macOS / iOS：先同时暂存原 HTTP 与 WebSocket 帧，验证真正未发布的独立分支，再合并；继续验证移动与远端标题编辑并发、作者撤销/重做、过期菜单和父正文引用。
4. Web 两账号加载同一原生 Cloud 对象：新建看板与新增记录、真实卡片移动和详情编辑、远端再移动、原撤销/重做、IndexedDB 独立进程重开。
5. 双方离开后，仅重启自有 Cloud 验证服务，以无缓存 Native 回读同一 Root1 / Row4 与正文引用，再归档实际截图、日志和源码摘要。Android 依用户约束不安装。

## 实际验证与视觉稿

Dataset Rust 66 项、Dataset Flutter 64 项（含三个宽度和真实长按拖动）、公共 Dataset SDK 3 项通过。Dataset、原生示例和 Web 静态分析通过。macOS 与 iOS 模拟器各通过 9 项真实在线 UI 与 3 项独立进程离线重开。记录详情继承父只读范围，不能借由卡片点击恢复写权限。

Web 两账号加载同一 macOS Cloud 对象，Alice / Bob 发布前分别为 3 视图 / 2 行与 2 视图 / 3 行；原编码帧与 HTTP 请求被暂存后再释放，最终三个视图共享三条原记录。Alice 实际通过卡片菜单移动、复用原详情编辑器改标题；Bob 新增原数字字段写入工时 12.5，再移动同一卡片。旧菜单操作被拒绝。作者通过真实撤销/重做入口编辑标题，远端分组与工时保持。主端 11、Bob 10、离线重开 6 项通过。

双方关闭协作连接后，重启本任务自有 Cloud 服务；无缓存 Native 回读 7 项通过，确认一个原 Root1 与三个 Row4，无卡片复制，正文引用未变。Cloud 继续使用 P19 的删除修复版本，没有新增协作协议或服务端数据库引擎。

早期 macOS 在线流程通过后，独立重开因两个进程构建间派生字段从不含 targets 升级为含 targets 而投影不一致；该失败保留诊断，不计作通过。固定生产源码后 macOS / iOS 完整重跑并通过。Web 验收脚本起初误以为基础 schema 有 amount 数字字段，在实际操作前修正为通过原命令新增 Web工时，再以原字段 ID 编辑；没有更改生产默认 schema 适配验收脚本。
