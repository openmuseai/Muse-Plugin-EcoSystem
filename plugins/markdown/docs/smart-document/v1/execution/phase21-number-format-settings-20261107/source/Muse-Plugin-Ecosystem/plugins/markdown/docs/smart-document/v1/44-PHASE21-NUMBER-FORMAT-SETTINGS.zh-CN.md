# P21：数字字段设置与完整金额分组（切片已验收）

承接 [P20 无损数字编辑](43-PHASE20-NUMERIC-CELL-INTEGRITY.zh-CN.md)，把已有 SDK 格式命令接入真实字段设置界面，并修复 P20 截图暴露的超长金额分组问题。继续以固定思源 `kernel/av/value.go` 的原值/格式/显示分离为基准。

## 产品与交互

点击数字列标题进入“数字字段设置”，在原字段名称输入框下增加“显示格式”。首批提供常规数字、美元、人民币、欧元、英镑；已有其他原格式可以保持，未对齐的百分比倍率、完整币种和更多样式另行推进。字段名称与显示格式在一次应用中提交，取消不写入；未修改直接关闭，不创建历史。Mobile 共用原对话框，至少 44px 的应用/取消入口，窄屏可滚动。

字段设置打开后捕获稳定字段 ID 和原字段摘要，远端变更后应用拒绝，保留本地名称和选择。错误文案沿用“字段已变化或名称无效，请重新检查”。这是本地过期草稿保护，不是分布式原子 CAS。更改格式只改变显示，不改变原数字字符串、独立 Row 对象或文档中的资源引用。

## 领域与复用

原 `ConfigureNumberField` 增加可选名称；字段校验与格式校验全部通过后，使用原 `Database.update_field` 在同一事务中更新名称与原 format/symbol，其他配置保留。未提供名称的既有 SDK 调用保持原行为。只读投影增加 `numberOptions.format`，界面不直接改写原 CRDT 或猜测未知字段。

金额显示继续复用原 `NumberTypeOption`、`NumberCellFormat`、`rusty-money 0.4.1` 的 Money、LocalFormat、Formatter、符号与舍入。实际缺陷来自原 LocalFormat 的有限 `[3,3,3]` / `[3,2,2]` 分组数组，超过三段后不继续分组。受控适配只在 AppFlowy 包装处重复原最后一段，覆盖 Decimal 的 29 位容量，不修改 money 库、注册表缓存、数据编码或 wire。客户端 Database 运行时由六个增至七个可逆补丁，原资格探针保持六个补丁。

原 money 源包、format/locale/Money 源码和许可证保存在 `smart_document/vendor/number_format_reference`，核对既有 Cargo.lock 的 crates.io checksum。思源/AppFlowy 的原参考仍见 `vendor/number_reference`。没有新增 CRDT、数字存储协议或货币引擎。Cloud 不执行本轮显示逻辑，沿用 P19 二进制。
