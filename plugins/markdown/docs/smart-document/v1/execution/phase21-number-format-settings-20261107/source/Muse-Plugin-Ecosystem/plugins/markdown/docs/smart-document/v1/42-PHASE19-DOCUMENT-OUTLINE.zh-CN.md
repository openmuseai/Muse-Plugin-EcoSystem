# P19：协作正文目录与跨端定位

承接 [P18 在线名单](41-PHASE18-USER-PRESENCE-ROSTER.zh-CN.md)，继续执行思源对齐计划。关联 [桌面交互规范](05-UX-SPEC.zh-CN.md) 与 [Mobile 产品交互稿](21-MOBILE-PRODUCT-UX.zh-CN.md) 的 MA-18。本轮增量已完成 macOS / iOS 模拟器 / Web 验收，证据单独冻结；既有冻结基线不修改，SY-30 与全量协作继续保持部分完成。

## 功能与复用

目录由正文 H1–H6 派生，支持跳级标题、层级展示、展开/收起、当前章节、点击定位、协作编辑后的更新。空标题显示“未命名标题”。引用、表格单元格、内嵌资源与未知扩展块形成独立内容范围，其内部标题不进入正文目录。显示标签最多 256 个 Unicode 标量；原正文不截断。未知或非法标题等级保留正文并显示部分格式不可用，不擅自改写等级。

参考固定思源 d3af9d5782082b379d45a69eedf4ebcfe8ba6889 的 kernel/model/outline.go、heading_number.go、render.go：采用前一个较低标题等级作为目录父项，展开状态与正文分离。参考 AppFlowy client 17e24f8232488fdac1213b17445af7dd4fb07ad2 的 outline_block_component.dart：复用已有标题/滚动机制。六份原始参考文件及许可证保存在 smart_document/vendor/outline_reference，含 Git blob 与 SHA-256 清单；原 vendors 工作区不修改。

运行内核直接调用现有 AppFlowy-Collab e59260e 的 Document.get_plain_text_from_block，旧版内联 delta 只经原 TextDelta 类型读取。Flutter 复用已固定 AppFlowy EditorScrollController 和虚拟列表，不重写编辑器、文档树或协作引擎。此增量不引入 Go Kernel、本地 SQLite 或新 CRDT。

## 领域分离

Document 内核在同一快照中派生 muse.document.outline/1 查询结果，包含稳定 blockId、标题等级、目录父 ID、显示深度和文本；不保存临时路径，不产生新的协作对象。查询不可用不能导致正文被重置。Dart DTO 验证版本、层级、重复身份和显示边界。

DocumentOutlineCoordinator 是每个编辑表面的本地视图状态：展开集合、当前章节和滚动控制器。桌面/移动宽度切换复用同一个协调器；切换资源后销毁旧协调器与迟到导航。当前展开状态仅在本次打开生命周期保留，未宣称跨次持久偏好。目录不参与内容撤销、不上传 Awareness、不更改授权；多人可以各自展开、阅读与定位。

点击后使用 objectId + blockId，在编辑器投影完成后重新解析实际路径。原虚拟列表包含产品页头，滚动时必须补上页头索引；跨异步边界再次检查块是否存在及当前权限/生命周期。不得依据已删除标题的旧路径定位到另一段正文。阅读跳转不设置编辑选区、不申请键盘焦点。

## 视觉与交互约束

Desktop/Web 沿用已冻结工具栏和内容宽度：底栏左侧目录开关控制左侧目录栏，正文继续使用原编辑区。目录栏宽 232，正文占剩余空间；窄于 700 的页面使用 Mobile 布局。

Mobile 保留“编辑 / 聊文档 / 目录 / 视图”阅读胶囊；目录使用原底部面板，标题栏和关闭入口保持原样。层级条目最小点击高度 44，展开箭头独立命中。点击标题先关闭面板再定位正文，保持阅读态。编辑态键盘上方工具区不增加第二个目录入口，不改变已冻结键盘布局。

正文折叠、聚焦模式、跨次偏好持久化、全部主题和所有思源块类型尚未由本轮实现。目录折叠只隐藏目录子项，不隐藏正文，不作为正文折叠验收证据。

## 开发与验收顺序

1. 内容查询：原文本 API、层级、隔离范围、空标题、未知格式、协作合并/撤销/重开；验证查询不产生文档字节变化。
2. 视图适配：桌面侧栏与底栏开关、Mobile 既有面板、44 像素命中、滚动章节、宽度切换和本地展开状态。
3. 真实 Cloud 两用户：标题改名、前缀插入、删除、作者撤销及重连；使用同一内容对象与原 WS 协议，确认目标块身份不漂移。
4. macOS/iOS 模拟器/Web 端到端 UI：长文档虚拟列表、含页头索引、只读导航、删除目标、关闭资源、离线重开和设计截图。Android 延续用户“不安装”要求。
5. 保存回执、源码输入与纯 WASM 哈希，更新对齐台账；所有本轮要求通过后再冻结证据。旧阶段证据不覆盖，不把阶段切片通过等同于完整思源或完整协作验收。

## 验收发现的原内核一致性缺陷与修复

真实 Web 切片发现：删除一个此前经原撤销恢复的标题后，本地目录已移除该块，但编码后新建内核会重新出现该标题。已将无凭据的原始内容状态固化为 rust/fixtures/restored-heading-before-delete.json，并在纯 Rust 复现；因此此失败不归为 Flutter 渲染或测试延时。

Yrs 0.23.5 的 TransactionMut.apply_delete 在删除范围首块为 GC 时，将整个后续遍历放在“首块是 Item”的分支内，跳过同一范围之后的有效块。修复仅将范围遍历移到该分支外，保留原起点切分、结束边界、原 Item 删除与后续 GC 逻辑。增加最小 GC+有效块测试与真实恢复标题快照回归，不新增 CRDT 或变更 Yrs update-v1 字节协议。

智能文档与已有 Dataset 使用原版本受控源码；Cloud 单独保存原版本包与此一处修复，不引入 Dataset 的可选单步撤销 API。两份 transaction.rs 哈希相同，可逆补丁、原 crates.io 校验和与许可证均可验证。仅重建并重启本任务隔离 Cloud，保留持久数据，原 AppFlowy 协作实现与权限路径继续使用。旧 P8–P18 二进制及源码证据保持冻结，不能声称本轮仍使用原 P8 二进制。

早期 Web 夹具的就绪条件与空回执缺陷单独保留；发现 GC 问题后的早期平台结果不作为修复后的最终验收。新增要求为：已恢复标题再次删除、编码重开、原 Cloud 新读取与三端 UI 必须一致。

此修复保留原 update-v1 编码，但旧解析器仍可能忽略 GC 后的删除尾部。正式部署须同时固定内容客户端与 Cloud 的补丁构建；协议字节兼容不能替代混合版本语义一致性。能力协商与升级门禁尚未实现，不能据本轮测试宣称任意旧客户端均可安全混用。先前已被旧解析器忽略且被压缩掉的删除，也不据此宣称能自动恢复；本轮保存原始回归输入，未重置任何既有资源。


## 最终验收结果

原文档 Rust 内核 27 项、Dataset Rust 50 项通过。补齐原仓库固定提交的外部编辑轨迹与兼容数据后，Yrs 完整库测试 305 项通过、1 项沿用上游 ignored；首次因七份外部数据缺失而失败的日志保留，未通过跳过用例来取得结果。完整库测试包含最小 GC 删除尾部回归，真实文档快照回归在修复前失败、修复后通过。

文档选定组 46 项与独立执行的 Cloud 重启用例 1 项、Dataset 完整组 51 项、Dataset 公共 SDK 3 项通过。文档选定组包括目录 DTO、跨断点展开状态、协作前缀插入后的稳定定位、只读嵌套标题导航与关闭后的拒绝定位；旧手动图片文件选择回读不在本轮通过计数中。

macOS / iOS 模拟器各 8 项主流程和 3 项无凭据重开通过，包含“已撤销恢复的标题再次删除 → 原 Cloud 新读回 → 作者再撤销”。Web 使用同一 macOS 创建对象，主端 8 项、Bob 5 项、离线 IndexedDB 重开 4 项，以及 Native 原 Cloud 读回 4 项通过。目录开关、层级折叠、原标题跳转均通过真实 UI 操作；Web 使用 Rust WASM + Flutter JavaScript，未宣称 Flutter --wasm 构建已通过。

六份实际服务的纯 WASM/绑定 JS 与构建报告匹配；含测试身份的应用 main.dart.js 仅保存摘要，不复制进证据。只重建和重启任务自己的隔离 Cloud，保留原资源与卷。旧阶段归档保持原样。Android 未安装、未运行；物理 IME、Windows/Linux、多用户规模、正文折叠、主题/长期偏好以及旧解析器混用仍未完整验收。
