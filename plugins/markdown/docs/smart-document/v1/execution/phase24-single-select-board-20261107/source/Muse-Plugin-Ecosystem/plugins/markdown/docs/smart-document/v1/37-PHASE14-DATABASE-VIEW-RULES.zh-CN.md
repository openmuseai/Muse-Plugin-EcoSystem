## 与思源的兼容边界

思源文本排序使用去除 emoji/不可见字符后的 GBK 字节近似拼音；AppFlowy 原文本排序使用字符串字典序。首轮保留 AppFlowy 明确语义并公开差异，不能宣称完成思源中文排序保真。思源相对日期、日期端点、来源块字段、全 18 字段/5 视图、分组计算继续单独对齐。P12 的显式 IANA 时区继续有效，不能引入 Go time.Local 或浏览器时区隐式求值。

未加载/无权限行保留为待加载记录，不能算作满足或不满足条件，也不能被排序视作普通空值。未知规则保留原内容；视图显示兼容状态并禁止从受误解的投影进行编辑。

## 已实现的规则边界

原文档/数据库资源身份、字段/记录身份不随筛选或排序变化。规则保存在原 View 的 filters/sorts，整份配置作为一次原 Root1 事务；行值仍在各自 Row4。打开草稿时记录规则 hash 和视图字段 schema hash，提交时双重检查；同伴改动后保留草稿并提示取消重开，不能覆盖新规则。

提取保留 12 份原文件摘要与 Git blob 身份，3 个原执行器、策略和 14 项原测试逐段与原文件比较；编译形状只剥离 PB、预填充与任务依赖。新增适配器严格处理旧扁平条件、原 AND/OR 树、空条件组三态、重复身份/字段、未知枚举、选项 ID 和类型变化。最多 32 个根条件、64 个节点、8 层、16 个排序键、64KiB 配置；每个内容输入 4KiB。原始未知规则不自动规范化后覆盖。

文本/链接、精确 Decimal 数字、复选框、单选/多选支持筛选；七类已支持字段可排序，包括原日期时间戳。文本继续原字典顺序，选项采用思源声明顺序，并明确使用严格前缀长度比较来保持排序关系有效；空值始终后置，等值保留手动记录顺序。日期筛选与思源相对日期/端点继续后续接入，不能把七类排序说成七类完整筛选。

每个视图分成 rows（可见结果）与 rowObjects（原始依赖的身份和加载状态）。网络订阅、ACL 判断、缺失记录恢复、创建顺序和全量修复仅使用 rowObjects；在线单元格位置与显示使用 rows。未加载记录继续显示待加载状态；被筛掉的已加载记录仍接收更新，满足条件后立即重投影。未识别的规则或被引用单元格的异常原编码使视图保留手动顺序、原数据和只读说明，不能静默算作空值。

| --- | --- | --- |
