# P23：多视图共享字段与原记录编辑（切片已验收）

承接 [P22 独立视图身份](45-PHASE22-LINKED-DATABASE-VIEWS.zh-CN.md)，补齐新建视图与新增字段发生在两条独立分支上的情况。继续使用原 AppFlowy FieldMap、FieldOrder、FieldSettings、DatabaseRow 和 type-option codec，不复制一套视图字段定义或表格引擎。

## 产品与交互

同一数据集中新建的字段应出现在各 Grid 视图中，保留同一字段 ID、名称、类型和配置。用户可在新视图直接点击原列标题编辑字段，再使用原单元格入口写入独立 Row4；另一账号看到相同字段定义和原行值。视图切换、独立筛选、旧名称草稿、局部键盘工具和稳定视图 ID 继续沿用 P22，不增加“同步列”或手动修复入口。

本轮补齐的是字段集合，字段显示管理不通过丢弃字段顺序实现。原 AppFlowy 的列可见性位于独立 FieldSettings.visibility；宽度、换行与完整隐藏列 UI 尚未开放。本轮保持原设置编码，不把可见列偏好当作访问权限。生产权限仍以资源与原对象授权为准。

## 领域与复用

固定思源 `AttributeView.KeyValues` 与 `LayoutTable.Columns` 已区分全局键值与视图列定义。运行时对应到已有原 FieldMap 与 View.field_orders。原 `Database.create_field` 明确向全部已知视图插入顺序及设置，但另一个客户端并发新建视图时尚不知道新字段，仍可能漏列；原 `get_fields_in_view` 在字段数与顺序数不一致时只警告，最终依照旧顺序返回。

新增负例先证明：原全局字段为 4，合并后的新视图仍只显示 3。修复保持 view.field_orders 原顺序，追加原隐藏主视图已知顺序中的缺少字段，最后按稳定字段 ID 追加全局 FieldMap 中剩余字段。字段定义始终取自原 FieldMap。此过程只派生查询，不在读取时写 CRDT、修改字段设置或另建 schema。

Grid 列投影、记录详情、筛选/排序命令预检共用同一有效字段集合。否则界面虽显示新列，命令仍会使用旧字段集合，错误地拒绝新字段筛选或漏掉旧字段草稿保护。fieldsHash 继续是本地乐观前置检查，不是跨客户端全局 CAS。未知类型和配置仍原样保留并只读，旧客户端的复制顺序行为和能力协商仍有独立缺口。

## 验收计划

领域先验证真正并发新建视图/字段，原始顺序不被查询改写，新字段的原 Row4 单元格可写并支持独立筛选/排序。真实 Cloud 继续先暂存 HTTP 与原 WS 编码帧，让 Alice 新建视图、Bob 新增字段和记录后再合并；验证新列出现在全部视图，原列标题改名和真实单元格写入被远端收到，原 Document 只保留资源引用。

随后检查三种屏宽回归、macOS/iOS 公共资源宿主、Web 同一原生对象、离线检查点和 Cloud 重启后的 Native 回读。完整字段删除/类型转换、隐藏列、计算与关系、全部 18 字段/5 布局和完整协作仍不由本轮替代；Android 依用户约束不安装。

## 实际验证与视觉关联

Dataset Rust 63 项、Dataset Flutter 60 项、公共 Dataset SDK 3 项通过；Dataset、示例、Web 静态分析通过。领域负例先证明 FieldMap 为 4、并发新视图仅显示 3 列；修复后同一原字段可进入 Grid、记录详情和筛选/排序，旧 fieldsHash 被拒绝，查询前后原 bundle 字节保持一致。

macOS / iOS 模拟器各通过 11 项真实 UI + 3 项独立进程重开。Alice 在原网络暂停时新建视图，Bob 新增字段和记录后再合并；新列出现于全部视图，Alice 通过原列标题设置改名，再在真实单元格中写入，Bob 收到同一原字段 ID 和 Row4 值。原视图独立筛选、作者撤销、位置清除、视图重做与原正文引用继续验收。

iOS 的两次早期失败保留为诊断：第一次尚未构建出屏外的第二行单元格；第二次使用完整宽列表的中心拖动，横向滚动后该中心处于屏幕外。最终从列表、组件与屏幕的可见交集内真实滑动，再严格命中单元格。未关闭严格命中检查、未修改原数据绕过 UI，也未以这些失败计作通过。

Web 对同一 macOS 原对象完成主端 13 项、Bob 9 项和离线重开 5 项；Cloud 独占服务重启后的 Native 回读 7 项通过。发布前 Alice 为 4 视图 / 2 行 / 4 字段，Bob 为 3 视图 / 3 行 / 5 字段；最终 5 个视图包含同一组 5 个原字段，共享 3 条独立记录，原生值“字段并发值”和 Web 值“Web字段值”分别保留。原生字段 ID、Web 新字段 ID 与各原生视图 ID 均跨端核对，未用复制数据库代替互通。
