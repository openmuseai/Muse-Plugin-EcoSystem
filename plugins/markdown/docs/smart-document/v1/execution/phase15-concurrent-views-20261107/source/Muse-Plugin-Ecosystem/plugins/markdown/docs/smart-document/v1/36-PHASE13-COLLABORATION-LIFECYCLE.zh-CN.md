## 领域分离与方案

内容版本、检查点保存代次、未接收的本机修改进度，以及协作会话授权/生命周期是四件不同的事。Dataset 的原 `_generation` 继续仅用于检查点；新增独立 collaboration epoch。文档沿用只承担会话失效的 generation。

有效权限变化、暂停/恢复、关闭会使之前的异步请求失效。每次读取、独立行初始化/交换、根交换、合并与保存之后都检查所属会话；成功与失败回包同等受约束。旧请求不能恢复写权限、改写较新拒绝/授权、再访问已释放的 FFI handle、继续引用已被移除的行，或者向新会话的检查点写回旧结果。

仍保持单个 HTTP 交换。恢复或新授权发生在交换期间时，旧请求结束后最多安排一次当前代次的修复；不并发重发写请求，不把重试当成新的内容命令。原服务端始终负责每个对象的当前 ACL，此适配器不授予权限。

关闭只等待本机检查点和合法的内容投影，不等待网络成功。原 HTTP provider 关闭并取消连接；即使某个已缓冲的响应无法取消，失效代次也会阻止它进入内容域。保存失败时继续保留唯一所有者和本机修改，显式重试；没有新增“强制丢弃”或静默新建空资源。

文档 realtime 的原 Manifest 接收分支曾把 HTTP 修复串入 socket 输入队列，导致关闭 socket 也等 HTTP。HTTP 修复现在由内容会话单独拥有，输入队列仅等待本地投影/保存；关闭后的补发受 `_closed` 约束。数据更新暂停时，内容端口拒绝新输入，显式的已认证权限通知仍可收窄权限。

这些逻辑分别位于 Document、Dataset 应用会话及其 realtime adapter。中立 collaboration contract、原协议、内容模型和资源身份没有增加编辑器类型判断或新的 CRDT 字段。

## 交互与验收计划

1. 真实 Cloud、公开 SDK、正文与独立嵌入表格、两个原 WS2 会话一起启动。
2. 使用真实表格编辑记录并完成根/行同步；只延迟已经由原服务器返回的一个 Row 4 HTTP 响应。
3. 通过实际“移除引用”菜单释放子会话；网络响应仍被持有时，所有者应释放。正文撤销恢复引用，创建一个新的唯一子会话并保留原记录。
4. 放行旧回包，验证旧会话、原检查点和新会话均不被回写；继续在界面编辑恢复后的行。
5. 发送原 Document Manifest，延迟实际 Full Sync 成功响应；关闭公开资源会话不应等待该响应。放行后仍不得修改已关闭的内容或本机检查点。
6. macOS/iOS 均需真实 UI、截图及无凭据新进程恢复。Web 保留同一内容核心/IndexedDB 验证，不能用 widget harness 代替浏览器或把模拟输入当成物理 IME。
