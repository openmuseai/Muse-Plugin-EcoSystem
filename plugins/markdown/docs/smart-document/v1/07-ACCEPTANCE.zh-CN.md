## 2. 验收用例规格

| 验收组 | 正常流程 | 必须覆盖的反例 / 通过标准 |
| --- | --- | --- |
| AC-01 | 新建/最近重开/重命名；独立入口和嵌入共用一对象 | 多资源并开隔离；删除引用不删源；只读历史不产生新写入 |
| AC-02 | 全部首版基础块与 marks、粘贴、拆合、移动、undo | 无环/单父/内容可达；IME/emoji/Unicode offset正确；不重建丢 ID |
| AC-03 | 2–5 人同段文本、格式、块操作，10人压力 | 乱序/重复/断线后规范化语义一致；服务端持久重开相同；内容正确不能只验二进制相等 |
| AC-04 | 离线写正文、退出、强杀、重开、恢复同步 | 已本机持久的操作可恢复；磁盘/配额失败不伪成功；数据集离线保持私有草稿 |

| AC-07 | 至少一类真实 Office 来源三端固定页/范围预览 | 显示来源/版本/渲染模式；坐标/字体/旋转正确；示例 JSON/无来源截图不算 provider |
| AC-08 | 图片/视频上传、显示/播放、替代文本 | 上传中断/重试、正文先到、大资源限制、历史附件 GC；不存在未经授权读取 |
| AC-09 | 结构读取→有界 patch→事件/来源→结果；后台无客户端窗口 | 同键重试不重复；目标变更/撤权/授权到期拒绝；取消后已提交可查，未提交不假成功 |

## 3. 测试分层与数据集

合同测试覆盖 Rust/Dart/服务端的序列化、未知字段与版本、错误/幂等、对象/锚点fixture；固定依赖升级时保留旧编码输入和输出语义对比。测试不是对序列化代码的机械复写，应验证协议兼容和错误边界。

内核测试覆盖命令、marks、结构、引用及 undo；协作测试采用固定并发序列和随机生成、乱序/重复/丢包/重连，至少从 500 个可重放随机 seed、每个 100 个有约束操作开始，保存失败 seed。规模在原型结果后调整，不把随机数量替代覆盖矩阵。

持久化测试对 append/flush/checkpoint/ACK 前后注入进程退出、存储失败与服务重启。数据集对事务/事件发布边界注入故障。应同时验证最终可见内容、业务不变量、去重和可恢复草稿。

格式语料至少含：基础文字/列表/任务/公式/代码/表格、包内与包外引用、附件、未知节点、AV/查询占位、长文、多语言/emoji。Office 包含真实 PDF/Word/Workbook 代表样本，以实际开放 provider 验收；未开放类型明确列未测。

产品端到端测试从资源中心进入，经真实编辑/保存/退出重开，不只挂载独立 widget。三端设备与浏览器版本、字体、输入法、网络、内容规模、核心/Host/产品版本写入报告。

## 4. 性能与稳定性口径

引用 PRD 目标：参考设备下本地输入 p95 <50 ms，50 ms RTT/5人远端可见 p95 <500 ms，1000块缓存 warm open p95 <2 s。10000块、10人、多Office/媒体为压力场景。需同时报告内存、CPU、浏览器核心加载、cold open、丢帧/长任务与队列积压。

这些是目标而非已达成指标；G0 冻结测试设备与采样方法。时延定义从输入/本地提交到目标可见状态，网络/缓存条件分组；不在测量中排除失败操作后只报成功分位数。

## 5. 证据格式与发布判断

每个用例记录：requirementId、caseId、版本/源码摘要、环境/语料、步骤、期望、实际、passed/failed/unrun、日志/截图或录屏、遗留限制。跳过网络/设备/服务条件时必须写 unrun，不能把 exit 0 当行为通过。

阻断级：已保存内容丢失、越权读写、破坏性迁移、不可恢复冲突、关键平台无法完成 P0 主线。阻断级为零且全部 P0 限定范围通过才可发布；低影响问题需有明确说明与跟踪任务。

灰度前演练：关新建/转换、限制高风险命令、保留未同步草稿、旧schema只读、从checkpoint+日志恢复、导入原包可取回。回退不能用旧编辑器覆盖新协作对象。
