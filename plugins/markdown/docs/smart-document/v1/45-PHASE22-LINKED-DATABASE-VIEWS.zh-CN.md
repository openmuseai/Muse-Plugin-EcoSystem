# P22：共享数据库的独立视图身份（切片已验收）

承接 [数据库适配设计](29-DATABASE-ADAPTER-DESIGN.zh-CN.md) 与 [P21](44-PHASE21-NUMBER-FORMAT-SETTINGS.zh-CN.md)，先开放原 Grid 的多视图创建、切换、命名和独立筛选，再沿用这些身份扩展看板、日历、列表和卡片。没有将一个本地显示模式冒充持久的独立视图。

## 产品与交互

原数据库工具栏保留视图下拉，新增“新增表格视图”和“视图设置”。内嵌与独立资源共用这套界面和一个数据库会话。创建视图只输入名称，取消不创建；应用创建稳定视图 ID，自动在当前编辑面选中。切换是本地 UI 状态，不修改正文资源引用、字段、记录或共享历史，也不改变其他协作者的当前视图。切换时清除原会话的旧单元格位置，避免协作者仍看到用户停留在此前视图；该清除只发送原临时 Awareness。

每个视图拥有原筛选和排序，记录仍是同一组独立 Row4。字段/单元格编辑与已有领域面板共用。重命名捕获稳定视图 ID 和旧名称，远端改名后拒绝旧草稿并保留输入；其他属性变化不冒充名称冲突。未修改设置直接关闭。写权限变化会禁用应用入口，最终仍由领域和真实服务端授权裁决。

撤销新建视图后，当前选择保持原 ID，显示“指定视图不可用，原引用保留”，不能自动跳去另一份内容。此时仍可显式选择已有视图，或重做恢复相同视图 ID。内嵌资源重新打开从原引用指定的视图开始，本地临时选择不伪装成持久偏好。移动端沿用原对话框、至少 44px 的操作目标和可换行工具栏。

## 领域与协作边界

命令继续调用原 `Database.create_linked_view` / `update_database_view`，存储是原 Root1 的 View Map，行值继续为 Row4。创建拒绝已有 ID、无效名称和视图上限；本轮不开放删除，避免把原 `delete_view` 对隐藏主视图的整库清除语义接入普通菜单。通用协作协议、服务端对象类型和资源/协作契约都不增加视图专用协议。

思源原 View 已分离 ID、名称、布局、筛选/排序和项目 ID。本轮对应到已有 AppFlowy 原结构，不复制思源的完整内核或应用壳。六份固定原源码/许可证见 `smart_document/vendor/linked_view_reference`，运行时实际使用既有固定 collab-database。

原 AppFlowy 会在新视图创建时复制当前行顺序，新增记录则只更新当时已知视图。两个客户端分别新建视图和记录，合并后新视图可能缺少并发新增的行。新增负例已证明原投影只出现一行，而主数据库已有两行。

本轮沿用原 `Database.get_all_row_orders` 的成员依据：隐藏 inline view 是数据库记录成员的权威，不能被误当成一个用户可选的可见视图。可见视图保留自己的原顺序，只读投影按原主成员关系排除失效记录，再按收敛的主顺序追加缺少成员。这样旧视图顺序既不会漏掉并发新增记录，也不能复活并发删除的成员。无查询时 CRDT 写入、后台修复或新序列协议；原始顺序和已缓存孤立行字节仍保留。记录读取、实时对象范围与投影使用同一成员边界；隐藏主视图本身也纳入作用域与行 ID 校验。

原 profile 的默认可见 Grid ID 仍按既有对象 UUID 派生，作为稳定的默认排序；其他视图按原创建时间和 ID 排序。界面在本地固定已选择 ID，远端新建视图不会抢走当前视图。未知布局继续保留原数据并提示能力尚未安装。旧 AppFlowy 前端若仍直接读取复制的 row_orders，可能保留原漏行行为；本轮只认证采用此适配的三端，混合旧客户端的能力协商与升级门仍开放。

## 实施与验收计划

领域用例覆盖真正并发新建视图/记录、并发删除后的旧顺序、重复 ID、过期名称、原作者单项撤销、原始字节保留和重开。三种屏宽覆盖内嵌创建、选择不写入、失效选择不回退、同 ID 重做及旧名称草稿。真实 Apple UI 和 Web 使用原 Cloud 两个账号，先阻挡 HTTP/原 WS 字节，让两条本地分支独立提交，再恢复登记和发布。

新增 Row4 必须先通过原 HTTP 登记，之后才能通过 WS 暴露引用，不能为了证明并发而跳过这个权限边界；实际回执明确包含 HTTP 与 WS 两条原通路。最终检查同一 Document / Dataset / View / Row 身份、独立筛选、资源引用未变、离线重开及 Native 回读。

实际通过 Dataset Rust 62 项、Dataset Flutter 60 项、公共 Dataset SDK 3 项。新增视图交互覆盖 320/430/1100 三种屏宽，含于 60 项；增加位置清除后，这 3 项又单独通过。macOS / iOS 模拟器各通过 9 项真实 UI + 3 项独立进程重开。Web 主端 10 项、Bob 8 项、离线重开 5 项；关闭两端在线会话并重启任务独占 Cloud 后，Native 对同一原对象回读通过 6 项。相关静态分析与固定源码映射通过。

Web 发布前 Alice 为 4 个视图 / 2 条记录，Bob 为 3 个视图 / 3 条记录，原编码帧分别被暂存，HTTP 均暂停；最终合并为 5 个稳定可见视图共享 3 条独立记录。Bob 的实际协作者面板先显示“Web团队视图 · 第 1 条 · 标题”，Alice 切换后变为“在线”，对应原 Awareness 清除。原 core 的 undo/redo 回执也记录了临时视图同一 ID 的消失和恢复，没有用伪造 JSON 代替原引擎。

[实际交互与视觉稿](linked-view-functional-review/index.html) 对照默认视图、独立筛选、旧名称草稿、位置清除和无回退状态；右侧检查区属于测试夹具。[冻结证据](execution/phase22-linked-database-views-20261107/result.json) 保留源码、回执、截图与逐文件清单。早期只有 8 项 UI 的原生运行和未含位置检查的浏览器回执保留为补充前的诊断，最终主证据使用 9 项 / 8 项协作端检查。

本轮没有认定完整 18 字段/5 类布局、删除/恢复、生产权限与全部协作完成。新建视图与新增字段同时发生时的列顺序还需要独立验证，不能把记录成员关系的通过当成全部 schema 并发都已通过；下一批沿用原字段定义补齐这条链路。Android 仍依用户要求不安装，完整 Desktop 范围和实体 IME/手机软键盘几何未认证。
