# WPS 智能文档 Mobile 实机参考

2026-11-05。参考 ID：**WPS-MOB-20261105**。依据用户手机上已经打开的 WPS 智能文档，通过现有 Android 镜像实际观察；不是将 Desktop 缩成窄屏猜测 Mobile。关联 [Mobile 产品/交互稿](21-MOBILE-PRODUCT-UX.zh-CN.md)、[可点击视觉稿](22-MOBILE-DESIGN-REVIEW.zh-CN.md)。

## 1. 实机已确认的功能区

| 区域 | 实际观察 | 对设计的约束 |
| --- | --- | --- |
| 阅读顶部 | 头像、分享、评论、三横文件菜单、数字资源切换、关闭 | 三横是文件/更多入口，不能误画成目录；顶部不塞桌面 Ribbon |
| 阅读底部 | 浮动胶囊：编辑、聊文档、目录、视图 | 目录在阅读底部明确可达；不常驻完整编辑工具栏 |
| 编辑顶部 | 完成、撤销、重做、三横文件菜单、数字资源切换、关闭 | 与阅读状态不同；真实不可用的 undo/redo 为禁用态 |
| 正文头部 | 添加封面、页面设置、大标题、作者/更新时间、评论数 | 标题和文档元信息属于内容头部，不用固定页头重复挤占正文 |
| 键盘功能区 | AI、＋、Aa、列表、对齐、图片、@、键盘开关 | 八项按此顺序；键盘出现时工具栏上移至其顶部，不留另一条重复底栏 |
| Aa | “调整样式”：文本类型、文本样式、字体颜色、高亮颜色 | 可滚动的底部面板，不能只提供 B/I/U 三个按钮 |
| Aa 文本类型 | 标题 1–6、正文；四列布局后续换行 | 完整设计覆盖 H1–H6；与旧首版 H1–H3 工程切片的差异须明确追踪 |
| Aa 文本样式 | 加粗、斜体、下划线、删除线 | 在所见 H1 光标状态，加粗不可用；不可推断所有状态都可直接取消标题固有字重 |
| Aa 颜色 | 完整字体色板，含渐变；高亮色板，含“无” | 普通颜色、渐变、高亮的存储/渲染能力分别验收，不能只画五个色块 |
| 列表 | 有序、无序、待办三个图标的紧凑浮层 | **键盘保留，不是大抽屉**；缩进不塞到此浮层里 |
| 对齐 | 左、中、右对齐，分隔线，减少/增加缩进 | **键盘保留，紧凑浮层**；所见根级减少缩进禁用；未观察到“两端对齐/行距”出现在该浮层 |
| 插入 | 表格、图片、云文档、本地文件、视频可见 | 多步资源选择保留插入位置；更深条目不凭猜测标成已实测 |
| 图片选中 | 空图片占位块含相册/拍照、云图片；右侧插入、复制、剪切、粘贴、删除、评论上下文 | 图片是块级状态，不能把它设计成普通正文选区；文字格式/列表/对齐按上下文禁用 |
| @ | 用户明确确认：**@ 用户** | 不合并“云文档”Tab；资源选择从“插入→云文档”进入 |
| AI | 浮动建议功能区＋AI 输入条＋深度思考，保留键盘；普通编辑工具区被 AI composer 替换 | 对齐这种组合布局；AI 菜单与模型能力接 Muse Agent |
| 文件/更多 | 另存、分享、打印；页面设置、查找替换；导出 Word/其他格式；分享模板；保存版本、历史版本、历史评论 | 功能清单完整保留并注明工程能力，不用三个“更多”按钮代替完整信息架构 |

## 2. 用户已明确收敛的范围

用户要求完整功能区，尤其键盘上方功能区。列表、对齐、Aa 和 @ 都已根据实机/用户确认修正，不沿用早期桌面缩放稿的推测。

用户进一步明确：**AI 保持当前样式，无需完整复刻 WPS AI 功能**。因此不继续追求 WPS AI 全部菜单、套餐、模型、生成内容或会员流程的保真；Muse 使用自己的 Agent 能力、范围、预览/应用与失败状态。这个收敛不削减普通写作和键盘功能区。

用户确认 @ 是用户提及入口；实际用户选择器布局尚未完整采集，因此视觉稿为 Muse 的标准成员搜索，不宣称该选择器已经精确复制 WPS。

## 3. 证据与边界

[结构化观察清单](mobile-functional-review/reference-observations.json)记录实机来源、所见状态、局部原始截图的路径/摘要，以及尚待核对项。原始参考截图保存在 `smart_document/.build/mobile-wps-reference/`，设计正文采用虚构成员和示例内容；版本化目录中的截图是我们自己的设计稿。

采集期间曾因镜像点击偏移误插入一个空图片占位块，已立即撤销，并确认该块消失、undo 恢复禁用。之后由用户在手机上展开 Aa、列表、对齐、@ 和 AI，代理只读取这些面板；用户随后主动选择列表等操作不作反向撤销。参考文档不是测试数据，也不用于运行本地原型的写入验证。

仍需区分：

* 已观察的是当前 Android 布局与上述入口；未证明分享/通知/历史恢复等后端行为。
* 阅读视图、目录、聊文档和完整系统/云选择器的深层布局仍可继续补证；设计稿已提供产品方案，不标作实机逐像素复刻。
* 当前可点击稿的选区、回复、恢复和 AI 建议是本地演示，不能代替真实 Flutter、Cloud、账号授权、Office 或输入法验收。
