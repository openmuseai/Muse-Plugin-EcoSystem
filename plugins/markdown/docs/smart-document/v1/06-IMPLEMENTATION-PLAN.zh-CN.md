## 4. G0 硬门槛

产品/交互基线现已冻结；G0 按 [当前视觉稿](12-FUNCTIONAL-ALIGNMENT.zh-CN.md) 的 WF 流程及 U1–U3 失败状态验证，再冻结最小工程协议。T02 增加中立 collab contract/fixture，T03 增加 fake provider 替换与独立领域验证，T06 收敛为 runtime + Cloud adapter + 内容 binding，T18 复用 registry 装配协作/UI 能力；具体 [包依赖门槛](09-COLLABORATION-PACKAGES.zh-CN.md)属于现有任务细化，不暗中承诺完整插件热安装平台。

| 门槛 | 验证内容 | 失败处理 |
| --- | --- | --- |
| G0-A 依赖可重现 | 补齐 vendor Collab path、锁 native/Cloud/WASM 版本，从干净源码构建 | 找回固定源码、对齐版本，禁止缓存偶然命中作成功 |
| G0-B 正文协作正确 | 双实例/三端、同段输入、乱序重复、离线重启、持久重开；树移动/拆合/父删子改 | 限制不可靠命令或重做绑定并重估；不能只看 WS 连接成功 |
| G0-C Web 可用 | 真核心 WASM、存储、IME/长文/语义、目标浏览器 | 决定 Flutter Web 修复或 DOM surface 备选；示例 JSON 不算通过 |
| G0-D 同屏真实材料 | 至少一个真实 Office provider 与正文并存，稳定来源/版本/坐标/文本 | 明示只读快照模式；若无法满足至少一类则不通过 SD-07 |
| G0-E Agent 闭环 | 读结构/来源 → 幂等 patch → 人类并发 → 冲突/提交 → 后台查询 | 补公共服务，不能以本机 UI 点击替代 |
| G0-F 目录/独立对象 | 独立数据集入口、嵌入视图、Agent 共用一对象；删除引用不删源 | 修正父文档私有模型，禁止复制数据到三个可写真源 |
| G0-G 扩展/权限/耐久 | 未知块保留、旧 schema 拒写、撤权、检查点、durable ACK 与恢复 | 增补 Cloud/SDK 合同并修订范围；不能客户端隐藏代替 |

G0 输出 passed/failed/unrun 与命令/日志/语料，任何环境跳过必须标记 unrun。它证明架构闭环，不代表产品验收完成。

## 6. 专项后续路线

0.2 优先根据试用反馈安排更多 Office provider、复杂引用、源码模式、数据集增强与扩展沙箱。Word/Excel 完整协作分别做操作模型 spike：稳定锚点/行列身份、公式与结构冲突、保存重开、撤销、在线与离线恢复。PPT/PDF 正文/媒体编辑也独立列能力矩阵，不用父文档协作测试替代。

思源保真按 S0 原始可取回 → S1 核心写作 → S2 引用/属性 → S3 AV/查询/知识工具 → S4 特殊运行时/API 推进。每项绑定固定思源语料、命令序列、并发结果与端上行为；不许以“保留未知字段”宣称已具备完整功能。

## 7. 风险、触发条件与责任

| 风险 | 负责人角色 | 触发与处理 |
| --- | --- | --- |
| Collab 路径/版本/协议不兼容 | 协作负责人 | G0 不能干净构建/互通则停承诺排期，锁正确 fork |
| 树结构/undo 数据破坏 | 核心负责人 | 任一可复现丢内容/无环失败阻断发布，限制命令并修复 |
| Web 输入/性能/依赖不可用 | Surface负责人 | G0 冻结备选 ADR；换 surface 要计入额外工作量 |
| Office 保存/渲染能力落差 | Provider负责人 | 按实际能力只读/不可用；至少一类三端真实 provider 是硬门槛 |
| 数据集/应用范围膨胀 | 产品/Cloud负责人 | 新关系/公式/细权限不计首版，走变更与重估 |
| 原始 CRDT 绕过命令授权 | Cloud负责人 | 查明所有写入口，补校验/限制路由；前端禁用不算修复 |
| 数据恢复/灰度回退丢修改 | QA/核心负责人 | 保存日志与检查点，关高风险新写，保留用户草稿 |
| 上游归档/许可/供应链 | 维护/发行负责人 | 固定版本、patch 与源码材料，保留持续升级责任 |

## 8. 灰度与回退

先对新对象开放，再开放显式格式转换；旧 userdata 不自动迁移。按 workspace/账号灰度，记录错误/恢复和性能，内容日志不采集全文/凭据。出现数据问题立即停止扩大灰度，可关新建/新转换或限制高风险命令。

回退产品壳与回退数据 schema 是不同操作：旧版不认识新格式则只读，不能直接用旧 Protyle 打开新 live 对象并覆盖保存。保留本机日志、Cloud checkpoint 和原始导入包。回滚前演练未同步草稿/附件与跨对象 manifest 的恢复。

## v1.2 功能对齐落地顺序

本轮交互/视觉基线改为 [12](12-FUNCTIONAL-ALIGNMENT.zh-CN.md)，不增加一套编辑真源，不要求重写 ioffice。T01–T24、18–28 周估算及原 P0 边界不变；G0 后按真实编辑能力重新估算，不能把视觉稿运行视为缩短核心开发的证据。

1. T03 纵向验证使用 WF-01/02/03：Flutter 三端选区/IME → 统一格式命令 → 正文状态 → 本机与云端回执。先解决写作，不先堆外围控制台。
2. T05/T08/T18 实现编辑主面、块操作、统一插入注册表、快捷键/Markdown 输入与 undo；T09/T14 验证子 surface 焦点和专业编辑器边界。
3. T06/T10 实现在线人/位置、真实共享角色、选区/块评论、通知去重和锚点失效；评论写入与正文写入各自授权。
4. T13 实现版本快照/恢复，T10 的评论历史及语义操作记录分别投影；恢复不回滚独立对象。
5. T20 整合当前功能稿；T21/T22 以 FA/WF 映射原 AC，补充真实网络、原始更新越权、IME、剪贴板、真机与性能证据。

指定页的精确布局核对作为视觉偏差清单持续收敛，不阻塞以上公共行为与合同的验证；尚未证实的 WPS 租户专有能力不直接进入排期。
