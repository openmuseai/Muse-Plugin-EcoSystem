## 当前字段增量

先接入原 `SingleSelectTypeOption` / `MultiSelectTypeOption`、`SelectOptionIds`、原 Field.type_options 和原 row cell。正式副本 `vendor/appflowy_database` 不新增补丁。`dataset/rust/src/choices.rs` 仅做命令边界验证和投影，不重新实现选项存储、CRDT、名称解析或撤销。

思源的 `kernel/av/av.go`、`value.go`、`capabilities.go` 和选项相关测试作为语义对照；其选项按名称/颜色/描述组织，原 AppFlowy 选项有稳定 ID，原调色板仅 9 色。当前必须保持差异显式：未实现的思源 14 色/自定义色、描述、导入映射不能静默变为近似值。本文没有把单选/多选基础编辑标为思源功能完整。

## 应用交互

新增字段继续进入既有 Grid 工具栏菜单。单选/多选创建表单包括字段名称和逐行初始选项；使用原稳定 ID，名称可含中文、emoji 和逗号。单元格显示带颜色的标签；点击后进入拥有独立草稿的选择面板，单选一次选择一个，多选保留用户选择顺序；清空/取消/应用均有明确入口。选择行触控高度至少 44px，面板在窄屏滚动；不显示内部对象 ID 或原始 CRDT JSON。

单元格草稿同时保存原 cell hash 和 field hash；在远端改值、改字段/选项后提交旧草稿必须拒绝，并保留当前草稿供用户查看。当前支持在新建字段时配置初始选项；已有选项的并发新增、重命名、删除、换色和权限审批尚未开放，后续必须验证原 type-option content 的原子 LWW 行为及服务端 schema 命令边界，不能把整个配置最后写入描述成无冲突的选项 CRUD。

原写入器的数组字符串分支按名称匹配，标量字符串还会按逗号拆分；适配器明确传递原 `{id: ...}` 对象数组，不能把 ID 字符串数组直接交给它。单选超过一个、重复 ID、未定义 ID 和不匹配的 schema 前置条件在候选验证阶段拒绝，不允许上游宽松转换静默清空值。

未知/非法选项配置继续保留原编码并只读。原 cell 中已失效的选项 ID 不自动丢弃；界面提示并允许用户明确移除或清空后重新选择。旧四类字段和完整 Bundle profile 继续可读，不复制一份新的数据库真源。
