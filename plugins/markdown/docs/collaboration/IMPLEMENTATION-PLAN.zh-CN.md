# 实施计划、风险验证与验收门槛

> 范围更新：用户已将目标明确为面向 Agent、异构元素同屏、Office 扩展与 Mobile/Web/Desktop 的智能文档平台。最新决议见 [智能文档架构](../smart-document/README.zh-CN.md)。本文件保留前一轮受限编辑器融合评估；其中 AppFlowy Document 作为永久公共模型的建议与 12–18 周排期不适用于新目标，依赖/源码事实仍可参考。

日期：2026-11-04。状态：计划，未执行；[选型](README.zh-CN.md) · [架构](DESIGN.zh-CN.md)。

## 1. 人员、范围及估算口径

推荐配置：2 名 Flutter/编辑器、1 名 Rust/CRDT、1 名服务端/数据、0.5–1 名 QA（含三端设备）。MVP 以 macOS、Android、iOS 为目标，沿用已有 Host 平台下限；浏览器、Windows/Linux 和商店审核另排。现有思源设备验收是本地兼容路径的历史证据，不能替代新 Flutter 协作的三端验证。

MVP 包括基础富文本/Markdown 输入、稳定块身份、基础引用/反链、只读嵌入、附件、双人至小组实时编辑、离线恢复、权限撤销、资源路由和显式原生格式转换。复杂 AV、SQL 查询嵌入、全局图谱、闪卡、全部 PDF 标注/OCR 和思源插件兼容不进入承诺范围。MVP 不要求同时开放两个可写编辑引擎。

12–18 周是含协议验证和首轮返工的估算区间；45–70 人周为有效工作量，人员并行并不均匀。若固定依赖无法获取、需要大规模改协议/AV，必须按 G0 结果重新估算。

## 3. G0：先花 2–3 周排除最大风险

### G0-A：可复现依赖

* 冻结思源、Flutter client、Web、Cloud 的 HEAD + 工作区 patch + 锁文件 + 内容摘要。识别嵌套仓库与本地 path patch 的真实来源，不修改用户已有未提交工作。
* 找回固定的 AppFlowy-Collab 依赖，修复迁移目录的 path；选定与 Cloud 兼容的 Rust client-api/Collab/Yrs 组合。生成 macOS/Android/iOS 最小插件构建，记录工具链与传递依赖许可证。
* 尝试从仅有锁定源码的干净目录重建，禁止依赖开发机上偶然残留的 Cargo/git cache；构建流程可以下载明确固定的依赖，但不能只在缓存命中时成功。

### G0-B：协议与数据互通

使用隔离 Cloud 和合成账号，先运行两个 Rust/Flutter 客户端实例：A/B 同对象文本插入、删除、格式变化，断网分别编辑，恢复后查询服务端持久结果再从新客户端打开。对比规范化语义内容和状态，不要求 CRDT 原始二进制字节完全相等。

冻结每个链路的 WS 路由、外层消息格式、update 编码、身份参数、ACK 语义、Doc schema。单独测试 Web Yjs `14.0.0-1` 与所选 Yrs 的交叉增量解码及 UTF-16 位置；Web 若非 MVP，可先只读或从本期排除，但不得声称三种客户端已经互通。

Cloud 源码有 v1/v2 并不等于现网代理开放了相同路由。此阶段验证隔离环境，不以本地成功替代生产环境合同。发现不兼容时优先对齐依赖，不通过盲目 envelope 转码隐藏文档语义差异。

### G0-C：扩展块与知识语义

制作带块引用、未知 IAL、嵌入、基础表格、附件和一个不支持 AV 的源包。验证导入、编辑相邻块、同步、服务端校验、快照重开、导出后信息保留；未知块不因编辑其相邻段落消失。若自定义块无法通过 Document 校验/索引/发布，先限制功能或修复扩展，不直接创建新 CollabType。

### G0-D：最难交互

真实 Flutter surface 验证中文/日文输入法、组合输入期间远端更新、emoji/ZWJ、跨块选区、代码块输入、表格粘贴与本地撤销。若现有 editor 在主平台基础输入不稳定，先修复或调整范围，不能只看菜单和静态渲染。

### G0-E：保存与恢复

通过插件资源入口确认：退出进程后可恢复本机已保存修改；断网不写伪“云端已保存”；云检查点与附件可以从全新客户端读取；一次历史恢复不会被旧离线队列静默覆盖。若 SDK 或服务端缺少所需状态，列明通用合同改动及负责人。

G0 交付一个“通过/失败/未测”的矩阵和可重复命令，至少 20 个针对风险的 fixture。通过代表小范围技术闭环，不代表产品已经上线。

## 4. B 路线的备选验证

若首版完整原生格式是硬要求，在投入 16–26 周之前，独立做 2–3 周 Protyle 绑定 spike（不能直接沿用 A 的 G0 结果）：

1. 一个段落的双向字符增量、富文本标记、中文 IME，两个实例同段编辑。
2. 拆/合块、移动、删除父块、远端更新选区、仅撤销自己的编辑。
3. Go AST 投影中断后从 CRDT 重建，不形成双写回路。
4. 列举所有仍能直接写入 Go 内核的入口，对首期未接入的 AI/模板/AV 等操作明确禁用或只读。
5. 使用包含 AV 的复杂原生文档验证功能边界，不用简单段落演示承诺完整保真。

若只能实现整块覆盖同步、合成输入丢失、双写一致性不可控，则该 spike 不通过。不以增加重试次数掩盖模型问题；回到单机兼容入口或重新缩减目标。

## 5. MVP 验收矩阵

| 类别 | 必须覆盖的情景 | 通过标准 / 证据 |
| --- | --- | --- |
| 文本收敛 | 2–5 人同段增删/格式、重复/乱序、短暂断线 | 全端规范化文档相等；测试预期中的文字无丢失；新客户端重开相同 |
| 块结构 | 插入、拆合、列表缩进、同块双移、父删子改、并发撤销 | 无环、单父、无无效引用；冲突行为可解释且有恢复路径 |
| 输入 | macOS 中文拼音、Android 主流 IME、iOS 中文；emoji/组合字符 | 合成不打断、无重复/乱码、光标和选择区行为正确；真实设备录像/步骤 |
| 撤销/选区 | A/B 连续输入后 A 撤销；远端插入发生在选区前 | 不撤销 B 的操作；选区及评论锚点正确移动或明确失效 |
| 本机耐久 | 持久化各边界强杀进程、移动端切后台、磁盘写失败 | 已明确本机保存的操作可恢复；未落盘错误不伪报成功 |
| 网络与同步 | 中断 WS、令牌刷新、消息重发、服务端重启、超时 | 最终补齐；队列有界且可诊断；无无限回传/双写循环 |
| ACL | workspace 外访问、只读账号写入、在线撤权、离线后撤权 | 服务端拒绝违规写；搜索/引用不泄露受限片段；草稿可按规则恢复 |
| 历史恢复 | A 恢复检查点，离线 B 带旧队列上线 | epoch/version 处理明确；不静默撤销用户恢复或丢掉 B 的草稿 |
| 导入导出 | 真实源包含列表/引用/附件/未知节点/AV | 原包不变；受支持部分语义往返；不支持项可见且可取回 |
| 附件 | 上传中断、正文先同步、同名资源、旧历史引用、GC | 没有静默断链；越权被拒；引用中的历史附件不被误删 |
| 资源接入 | 创建/最近重开/移动/复制引用/只读历史/多资源并开 | Host 无格式专用分支；同一资源不被双引擎同时写；资源身份稳定 |
| 云耐久 | 客户端收到 ACK 后 Cloud 重启，从新设备打开 | 按明确 ACK 合同验证；durable checkpoint 可重读并校验 |
| 规模 | 长文、1000–10000 块、批量粘贴、5–10 人压力 | 达到固定设备/网络下性能预算，无明显 UI 冻结和日志失控 |

首期性能预算建议（目标，非测量结果）：指定参考桌面及移动设备、固定 50 ms RTT 网络下，本地连续输入 p95 < 50 ms，远端可见 p95 < 500 ms；1000 块本地 warm open p95 < 2 秒；后台恢复首次可编辑 < 3 秒（已有缓存）。10000 块、10 人作为压力与退化检查，不承诺与小文档同一指标。G0 记录基线后再冻结具体预算；cold start、网络抖动和导入耗时独立统计。

自动化重点验证序列化互通、随机并发及树不变量、恢复/迁移；设备验收覆盖输入法/选区/键盘/生命周期。对每个拟提交的代码改动执行与风险对应的测试，不为纯文档修改运行整个产品构建。

## 6. 风险登记与应对

| 风险 | 概率 / 影响（判断） | 前置措施 | 触发后的选择 |
| --- | --- | --- | --- |
| Collab 依赖缺失/版本不匹配 | 高 / 高 | G0-A/B、锁定源与 fixture | 补齐固定 fork、对齐版本并重估；不直接升级全部依赖 |
| 思源功能范围失控 | 高 / 高 | MVP 清单和原生兼容入口 | 后置 AV/SQL 等；若变为硬要求改选 B 并重估 |
| 文档数据丢失 | 中 / 极高 | 单一写入源、本地日志、检查点、故障注入 | 停止扩大灰度；只读与恢复草稿，禁止旧快照覆盖 |
| 撤销/树移动语义错误 | 中高 / 高 | 定向并发用例、确定性修复合同 | 限制复杂操作到受控流程，不用最终收敛替代正确性 |
| Flutter IME/大文档卡顿 | 中 / 高 | G0-D、设备基线、局部刷新 | 修复/裁剪首期块类型；不能靠隐藏输入问题上线 |
| ACL 与跨引用泄露 | 中 / 高 | 服务端对象检查、权限感知索引 | 引用显示受限占位；关闭未授权投影 |
| 上游停止维护 | 已发生（Cloud 归档） / 长期高 | Muse 固定 fork、维护责任与安全更新预算 | 自维护协议/依赖；不等待上游提供新特性 |
| 授权边界误判 | 中 / 高 | 按锁定依赖列许可和对应源码 | 调整依赖或履行许可；不能靠 WebView/语言改写规避 |

## 7. 灰度、回退和兼容入口退出

初期只对新建协作资源开放 Flutter；原生资源默认保持 Protyle。转换产物独立保存，原件一直可取回。按 workspace 或账号灰度，不改变全局 `.md` handler 优先级。

遇到数据一致性缺陷时，可关闭新建/新转换，并让已创建协作资源进入只读或停用高风险命令；保存本地日志和服务器检查点。不能简单把同一协作资源自动交给 Protyle 打开并写回，因为其权威格式不同。降级版本也必须拒绝不认识的 schema/epoch。

兼容入口只有同时满足下列条件才考虑退出：受支持格式样本全量语义往返、关键编辑/知识能力达标、三端真实设备通过、既有用户数据迁移与恢复经过演练、所有剩余不支持功能有明确产品决策。未满足时并存是受控兼容策略，不算已完全统一 Flutter。

## 8. 本次文档工作的完成定义

本次交付为技术分析、推荐架构、阶段计划与可核查证据；未修改编辑器、服务端或 vendor 源码，未运行协作 PoC，未验证生产部署状态，也未把既有验收文件当成本方案的新测试结果。实施应从 G0 开始。
